\section{Overview}

The merge-and-shrink (M\&S) framework builds an admissible heuristic for
cost-optimal classical planning by constructing a compressed abstract
representation of the planning task.  Starting from one atomic transition
system per planning variable, the algorithm iteratively:

\begin{enumerate}
  \item \textbf{Shrinks} two chosen systems to keep their sizes manageable, then
  \item \textbf{Merges} them into a single system via synchronized product.
\end{enumerate}

The resulting abstract system encodes goal distances that lower-bound the true
cost to the goal, yielding an admissible (and, under standard conditions,
consistent) heuristic.

\section{Algorithm Flow}

The entry point is \texttt{MergeAndShrinkAlgorithm::build\_factored\_transition\_system()}.
After creating one atomic transition system per variable and optionally pruning
unreachable or dead-end states, it runs the main loop:

\begin{lstlisting}[caption={Main loop pseudocode}]
while |active factors| > 1:
    (i1, i2)  <- merge_strategy.get_next()          # 1. select pair
    label_reduction.reduce(i1, i2)                   # 2. optional, before shrink
    shrink_before_merge(TS[i1], TS[i2])              # 3. shrink both
    label_reduction.reduce(i1, i2)                   # 4. optional, before merge
    i  <- fts.merge(i1, i2)                          # 5. synchronized product
    prune(TS[i])                                     # 6. remove dead states
    if not fts.is_factor_solvable(i): break          # 7. early termination
\end{lstlisting}

% ─────────────────────────────────────────────────────────────────────────────
\section{Merge Strategies}

The merge strategy decides \emph{which} pair of factors to combine next.
Three families are implemented.

\subsection{Precomputed (\texttt{merge\_strategy\_precomputed.cc})}

A \texttt{MergeTree} --- a full binary tree over variables --- is constructed
before the loop and consulted at each step.  The next merge is always the
leftmost sibling-leaf pair in the remaining tree.  The canonical choice is a
\emph{linear} tree ordered by reverse level in the causal graph.

\subsection{Stateless (\texttt{merge\_strategy\_stateless.cc})}

Pairs are chosen dynamically using a \texttt{MergeSelector} that scores every
candidate pair and keeps only those that maximise the score.  Available scoring
functions include:

\begin{itemize}
  \item \textbf{Goal relevance} --- prefer factors that share goal variables.
  \item \textbf{DFP} --- the classic Dräger--Finkbeiner--Podelski criterion.
  \item \textbf{MIASM} --- maximise abstract state space size reduction.
  \item \textbf{Total order} --- tie-breaking by a fixed variable ordering.
\end{itemize}

\subsection{SCC-based (\texttt{merge\_strategy\_sccs.cc})}

Merges are first restricted to strongly connected components of the causal
graph, which are processed in topological order.  A configurable fallback
strategy handles merges across SCCs.

% ─────────────────────────────────────────────────────────────────────────────
\section{Shrink Strategies}

Before merging, each factor is reduced so the product stays within the
\texttt{max\_states} budget.  All strategies compute a
\emph{state equivalence relation} --- a partition of states into equivalence
classes --- which is then applied to the transition system.

\subsection{Size Computation (\texttt{utils.cc})}

Let $s_1, s_2$ be the current sizes and $M$ the hard limit.  Target sizes
$(t_1, t_2)$ satisfy:

\begin{align}
  t_i &\leq \texttt{max\_states\_before\_merge} \\
  t_1 \cdot t_2 &\leq M
\end{align}

If both $s_i > \sqrt{M}$, both targets are set to $\lfloor\sqrt{M}\rfloor$.
Otherwise the larger one is reduced to $\lfloor M / s_{\min} \rfloor$.

\subsection{Bisimulation (\texttt{shrink\_bisimulation.cc})}

The strongest strategy.  States $s, s'$ are bisimilar if they have identical
goal-distance $h$ and, for every abstract transition $(s, \ell, t)$, there
exists a transition $(s', \ell, t')$ with $t \sim t'$, and vice versa.

\paragraph{Algorithm.}
\begin{enumerate}
  \item \textbf{Initialise groups.}  States are partitioned by $h$-value:
        goal states form group~0; states with $h = i > 0$ form group~$i$;
        dead-end states ($h = \infty$) get a dedicated group.
  \item \textbf{Compute signatures.}  Each state $s$ gets a signature
        \[
          \sigma(s) = \bigl(h(s),\; \text{group}(s),\;
            \{(\ell, \text{group}(t)) : (s,\ell,t) \in T\}\bigr).
        \]
  \item \textbf{Refine.}  States with identical signatures are merged into one
        group.  Repeat until a fixpoint is reached.
\end{enumerate}

With \texttt{greedy=true}, only $h$-optimal transitions are included in the
signatures, preserving at least one optimal plan while allowing more aggressive
merging.

\subsection{Bucket-based (\texttt{shrink\_fh.cc}, \texttt{shrink\_random.cc})}

Simpler strategies that group states into buckets by $(f, h)$ values or
randomly, then merge states within each bucket to meet the target size.

% ─────────────────────────────────────────────────────────────────────────────
\section{Label Reduction (\texttt{label\_reduction.cc})}

Action labels that induce \emph{identical transitions} across all relevant
factors can be merged without changing the abstract distances.  This reduces
the branching factor of every transition system at no precision cost.

Three application timings are supported:

\begin{itemize}
  \item \texttt{TWO\_TRANSITION\_SYSTEMS} --- only for the next merge pair.
  \item \texttt{ALL\_TRANSITION\_SYSTEMS} --- across all active factors.
  \item \texttt{ALL\_TRANSITION\_SYSTEMS\_WITH\_FIXPOINT} --- iteratively until
        no further reduction is possible.
\end{itemize}

% ─────────────────────────────────────────────────────────────────────────────
\section{Distance Computation (\texttt{distances.cc})}

After each merge, two breadth-first searches are run on the new factor:

\begin{itemize}
  \item \textbf{Forward BFS} from the initial abstract state computes
        $\mathit{init\_distance}(s)$ for every state $s$.
  \item \textbf{Backward BFS} from all goal states computes
        $\mathit{goal\_distance}(s)$ (i.e.\ $h(s)$).
\end{itemize}

States with $\mathit{init\_distance} = \infty$ are unreachable;
states with $\mathit{goal\_distance} = \infty$ are dead ends.
Both can be pruned to keep the factor compact.

% ─────────────────────────────────────────────────────────────────────────────
\section{Abstract State Representation (\texttt{merge\_and\_shrink\_representation.cc})}

After the algorithm terminates, the heuristic is stored as a tree of lookup
tables mirroring the merge tree:

\begin{itemize}
  \item \textbf{Leaf nodes} (\texttt{MergeAndShrinkRepresentationLeaf}) map
        concrete variable values to abstract states via a flat array.
  \item \textbf{Internal nodes} (\texttt{MergeAndShrinkRepresentationMerge})
        combine two children through a 2-D table indexed by the children's
        abstract state indices.
\end{itemize}

Once the algorithm finishes, \texttt{set\_distances()} replaces every abstract
state index with its goal distance, so that evaluating the heuristic for a
concrete state is a pure table lookup with no search.

\section{Axioms}

Classical planning tasks may include \emph{derived variables} whose values are
not set by operator effects but are instead inferred by \emph{axiom rules}.
An axiom rule is a Horn clause of the form

\[
  \text{head} \leftarrow c_1 \wedge c_2 \wedge \cdots \wedge c_k,
\]

where the head assigns a value to a derived variable and each condition $c_i$
is a fact over any variable (regular or derived).  The planner evaluates all
applicable axioms after every state transition to obtain the complete state.

\subsection{Data Structures (\texttt{axioms.h})}

Three structures make up the evaluator:

\begin{description}
  \item[\texttt{AxiomLiteral}] Represents a single fact $\langle\mathit{var},
        \mathit{val}\rangle$ of a derived variable.  It carries a list
        \texttt{condition\_of} pointing to every rule that mentions this fact as
        a condition, enabling forward propagation without a full scan.

  \item[\texttt{AxiomRule}] Represents one Horn clause.  It stores the target
        variable and value (\texttt{effect\_var}, \texttt{effect\_val}), the
        total number of conditions (\texttt{condition\_count}), and a mutable
        counter \texttt{unsatisfied\_conditions} that is decremented as
        conditions become true during evaluation.  When the counter reaches
        zero the rule fires.

  \item[\texttt{AxiomEvaluator}] The top-level class.  It holds a 2-D table
        \texttt{axiom\_literals[var][val]}, the flat list of all rules, and
        per-layer \texttt{NegationByFailureInfo} entries that record which
        derived variables must fall back to their default value at the end of
        each layer.  The \texttt{queue} vector is an instance variable so its
        heap allocation is reused across calls.
\end{description}

\subsection{Stratification (\texttt{translate/axiom\_rules.py})}

Before search begins, the translator partitions axiom rules into \emph{layers}
so that the evaluation order is well-defined.  The stratification algorithm:

\begin{enumerate}
  \item Builds a dependency graph over derived variables.  A \emph{positive}
        dependency $u \to v$ arises when $v$ appears positively in the body of
        a rule whose head involves $u$; a \emph{negative} dependency arises
        when $v$ appears negated.
  \item Computes strongly connected components (SCCs) of the dependency graph.
  \item Assigns layers such that:
        \begin{align*}
          \text{layer}(\text{pos.\ dep.}) &\leq \text{layer}(\text{head}), \\
          \text{layer}(\text{neg.\ dep.}) &<   \text{layer}(\text{head}).
        \end{align*}
        The strict inequality for negative dependencies guarantees that when a
        rule consults the negation of a derived variable, that variable's value
        is already finalised.
\end{enumerate}

Cycles through negative edges are forbidden; the translator aborts with an
error if they are detected, because such programs have no well-defined
all-models semantics.

\subsection{Evaluation Algorithm (\texttt{axioms.cc})}

\texttt{AxiomEvaluator::evaluate()} implements \emph{stratified forward
chaining with negation by failure}.  It runs once after every operator
application and on the initial state.

\paragraph{Phase 1 — Initialisation.}
\begin{enumerate}
  \item Set every derived variable to its \emph{default value} (the
        negation-by-failure value, stored in \texttt{default\_values}).
  \item Reset all \texttt{unsatisfied\_conditions} counters to their static
        initial values.
  \item Seed the propagation queue with the facts of all \emph{regular}
        (non-derived) variables, since their values are fixed by the operator
        effects and are never re-derived.
\end{enumerate}

\paragraph{Phase 2 — Layered forward chaining.}
For each axiom layer $\ell$ in order:

\begin{lstlisting}[caption={Per-layer evaluation pseudocode}]
while queue is not empty:
    lit = queue.pop()
    for rule in lit.condition_of:
        rule.unsatisfied_conditions -= 1
        if rule.unsatisfied_conditions == 0:
            state[rule.effect_var] = rule.effect_val
            queue.push(axiom_literals[effect_var][effect_val])

# Negation by failure (skipped for the last layer)
if layer < last_layer:
    for (var, default_lit) in nbf_info_by_layer[layer]:
        if state[var] == default_values[var]:   # not yet derived
            queue.push(default_lit)
\end{lstlisting}

After the inner loop drains, any derived variable in layer $\ell$ that was
never fired retains its default value.  The negation-by-failure step then
queues that default fact so that rules in \emph{later} layers that depend on
its negation can fire.  The last layer is exempt because no later layer
depends on it, saving unnecessary work.

\subsection{Negation by Failure and \texttt{DefaultValueAxiomsTask}}

The evaluator treats negation implicitly: a derived variable that has not been
derived is assumed to hold its default value, which represents the negation of
its derived (non-default) value.  Some components — notably heuristics that
treat axiom rules as operators — require \emph{explicit} rules for the default
value.  \texttt{DefaultValueAxiomsTask}
(\texttt{tasks/default\_value\_axioms\_task.cc}) provides this by rewriting the
task:

\begin{description}
  \item[Exact transformation (acyclic case).] The conditions under which a
        derived variable $v$ is \emph{not} derived are expressed in DNF by
        negating the disjunction of all rule bodies that could derive $v$.
        Each DNF clause becomes an explicit axiom rule with head
        $v = \mathit{default}$.

  \item[Approximate transformation (cyclic case).] When derived variables are
        mutually dependent, constructing the exact negation would be
        semantically incorrect.  Instead, a single rule with an empty body is
        inserted: $v = \mathit{default} \leftarrow \top$.  This
        over-approximates the default condition but is always safe.
\end{description}

\subsection{Integration with State Generation}

After every operator application, \texttt{StateRegistry} calls
\texttt{axiom\_evaluator.evaluate(new\_values)} before storing the successor
state (\texttt{state\_registry.cc}).  For tasks with axioms the state is kept
in unpacked (vector) form during evaluation for efficiency, then packed into
the registry's compact representation.  The initial state is also axiom-closed
during construction in \texttt{root\_task.cc}.

The planning-task API in \texttt{task\_proxy.h} exposes derived variables
through three predicates:

\begin{itemize}
  \item \texttt{VariableProxy::is\_derived()} --- true iff
        \texttt{axiom\_layer} $\neq -1$.
  \item \texttt{VariableProxy::get\_axiom\_layer()} --- returns the
        stratification layer for evaluation ordering.
  \item \texttt{VariableProxy::get\_default\_axiom\_value()} --- returns the
        negation-by-failure value.
\end{itemize}

Axiom rules are accessed via \texttt{AxiomsProxy}, which iterates over them
analogously to operators.  Their cost is always 0 regardless of the task's
cost type.

\subsection{Example: Philosophers Domain}

The Philosophers benchmark
(\texttt{misc/tests/benchmarks/philosophers/domain.pddl}) illustrates axioms in
practice.  A derived predicate \texttt{blocked} captures whether a process is
blocked from acquiring a resource, using existential quantification over
complex conditions:

\begin{lstlisting}[caption={Derived predicate in Philosophers domain}]
(:derived (blocked ?p - process)
  (exists (?s - state)
    (exists (?pt - proctype) ...)))
\end{lstlisting}

After translation, each such derived predicate becomes a set of grounded axiom
rules assigned to a layer determined by the stratification algorithm.  The
evaluator then maintains the \texttt{blocked} values automatically as the
elevator-style resource allocation proceeds.

\section{Incorporating Axioms into Merge-and-Shrink}

The current M\&S implementation aborts when the task contains axioms.  The
ideas below sketch how to lift that restriction by extending the factored
transition system with \emph{axiom-induced abstract factors}, one per derived
goal variable, kept small by quasi-bisimulation shrinking.

The approach proceeds in two phases: axioms in \textbf{goal conditions} first,
then axioms in \textbf{operator preconditions} using the same strategy.

% ─────────────────────────────────────────────────────────────────────────────
\subsection{Core Idea}
\label{sec:core-idea}

Instead of blocking on axioms, extend the factored transition system
$F(\mathcal{P}) = \langle \Theta_{v_1}, \ldots, \Theta_{v_n} \rangle$ with
additional factors $\Theta_{S,d}$, one per derived goal variable $d$.  Each
such factor encodes the structural information needed to decide whether $d$ is
satisfied, without materialising the full synchronized product.  A
\emph{reconstruction property} guarantees no information is lost:

\[
  \Bigl(\bigcap_{\Theta_i \in S} \mathcal{L}((\Theta_i^G)^A)\Bigr)
  \;\cap\;
  \mathcal{L}(\Theta_{S,d})
  \;=\;
  \mathcal{L}\!\Bigl(\bigl(\bigotimes_{\Theta_i \in S} \Theta_i\bigr)^{\!A}\Bigr),
\]

where $(\cdot)^A$ re-marks the goal states of a transition system to be
exactly those satisfying the projected axiom $d$, and $\Theta_i^G$ is
$\Theta_i$ with every state designated as a goal.

\subsubsection*{Implementation Overview}

The implementation is divided into five steps, each building on the previous
one:

\begin{description}
  \item[Step 1 — Compute Primary Representations.]
    For each derived goal variable~$d$, identify the set~$S_d$ of primary
    (non-derived) variables that $d$ depends on by scanning the axiom rules
    whose head is $d$ and collecting the primary-variable conditions that appear
    in those rules.  Derived conditions are over-approximated (treated as always
    satisfiable) to keep the computation simple.
    \emph{New files:} \texttt{primary\_representation.h/.cc}.

  \item[Step 2 — Implement the $(\cdot)^A$ Transformation.]
    Define the goal-restriction operator $(\cdot)^A$: given a transition system
    and a derived goal variable~$d$, re-mark the abstract states whose concrete
    pre-images satisfy $d$.  This transformation is the theoretical backbone
    used in Step~3.
    \emph{Key file:} \texttt{fts\_factory.cc}.

  \item[Step 3 — Build Axiom-Induced Abstract Factors.]
    For each derived goal variable~$d$, construct the factor $\Theta_{S_d,d}$:
    a product system over $S_d$ whose goal states are exactly those satisfying
    $d$.  Each factor is appended to the factored transition system (at an index
    $\geq$ \texttt{num\_variables}) before the main M\&S loop begins, and is
    immediately shrunk with quasi-bisimulation before any merging takes place.
    \emph{Key files:} \texttt{fts\_factory.cc},
    \texttt{merge\_and\_shrink\_algorithm.cc}.

  \item[Step 4 — Quasi-Bisimulation Shrinking.]
    Reduce each axiom-induced factor using quasi-bisimulation: a bisimulation
    variant that preserves goal/non-goal distinctions and ensures the resulting
    heuristic remains admissible.
    \emph{New files:} \texttt{shrink\_quasi\_bisimulation.h/.cc}.

  \item[Step 5 — Integration into the Main Loop.]
    Confirm end-to-end correctness on tasks with derived goal predicates.
    The two integration tasks originally planned for this step — removing the
    axiom abort (\texttt{verify\_no\_axioms()}) and updating the
    language-support annotation — were carried out as part of Step~3.
    Step~5 validates the full pipeline on the Philosophers benchmark
    (p01, p02, p03) and confirms admissibility and informativeness.
    No new files are modified in this step.
\end{description}

% ─────────────────────────────────────────────────────────────────────────────
\subsection{Step 1 — Compute Primary Representations}
\textbf{New files:} \texttt{merge\_and\_shrink/primary\_representation.h},
\texttt{merge\_and\_shrink/primary\_representation.cc}

\subsubsection{The Problem with Explicit Enumeration}

The primary representation $S_d$ of a derived variable $d$ is defined over
all primary variables jointly: it is the set of complete primary-variable
assignments under which $d$ evaluates to true.  Storing $S_d$ explicitly
requires enumerating all such assignments, which is exponential in the number
of primary variables and therefore infeasible in practice.

\subsubsection{What We Actually Need}

For the $(\cdot)^A$ goal transformation in Step~2, we do not need $S_d$ in
full.  We only need its \emph{projection} onto each individual variable's
domain: for primary variable $v$ and value $c$, is there any global primary
assignment with $v = c$ that lies in $S_d$?  This per-variable boolean
information is sufficient to re-mark goal states in atomic factors.

\subsubsection{Computing the Projection from Axiom Rule Structure}

Rather than running the axiom evaluator over all possible states, we read the
axiom rule structure directly.  An axiom rule for $d$ has the form:

\[
  d = \text{true} \;\leftarrow\; c_1 \wedge c_2 \wedge \cdots \wedge c_k
\]

where each condition $c_i$ is a fact $\langle v_i = w_i \rangle$ over either
a primary or a derived variable.  A value $c$ of primary variable $v$ is
compatible with $d$ being derived if there exists a rule for $d$ whose
conditions are satisfiable with $v = c$.  A rule's conditions are satisfiable
with $v = c$ in two cases:

\begin{itemize}
  \item The rule has \textbf{no condition on $v$}: then $v = c$ does not
        conflict with the rule, and setting other variables to satisfy the
        remaining conditions makes the rule fire regardless of $v$'s value.
        Every value of $v$ is therefore compatible via this rule.
  \item The rule has \textbf{a condition $v = c$ specifically}: then $c$ is
        exactly the value that satisfies that condition, so the rule can fire
        with $v = c$ (assuming the other conditions can be satisfied).
\end{itemize}

Conditions on \emph{derived} variables are ignored.  Determining whether a
derived condition is satisfiable would require recursively computing primary
representations of other derived variables and checking conjunctions across
them — a constraint-satisfaction problem.  Instead, we conservatively assume
all derived conditions can always be satisfied.  This gives an
\emph{over-approximation} of $S_d$: we may mark a value $c$ as compatible
when it is not truly compatible, but we never miss a value that is compatible.
Over-approximation is the safe direction of error for an admissible heuristic,
because it can only cause the heuristic to underestimate the true cost.

\subsubsection{Data Structure}

The result is stored in a two-dimensional boolean array
\texttt{compatible\_values[var\_id][val]}, where \texttt{var\_id} ranges over
primary variables and \texttt{val} over their domain values.  The full row
\texttt{compatible\_values[var\_id]} is the projection of $S_d$ onto variable
\texttt{var\_id}.  Derived variables are excluded from the array entirely —
they are not part of the primary variable space $V$.

\subsubsection{Implementation: \texttt{PrimaryRepresentation}}

The class \texttt{PrimaryRepresentation} in
\texttt{primary\_representation.h/.cc} encapsulates this computation.  Its
constructor takes the \texttt{TaskProxy} and the id of the derived variable
$d$, and its single public method \texttt{is\_compatible(var\_id, val)} exposes
the projection.

\paragraph{Constructor logic.}
\begin{enumerate}
  \item \textbf{Allocate the array.}  For each primary variable, allocate a
        \texttt{vector<bool>} of its domain size, initialised to \texttt{false}.
        Derived variables receive an empty entry and are skipped throughout.

  \item \textbf{Determine the default value.}  Each derived variable has a
        \emph{negation-by-failure} (default) value — the value it holds when no
        axiom rule fires.  Rules that derive $d$ to its default value are not
        of interest (they do not make $d$ true), so they are skipped.

  \item \textbf{Scan axiom rules.}  For each axiom rule whose head is
        $d = \text{non-default}$:
        \begin{enumerate}
          \item Collect all conditions on \emph{primary} variables into a map
                \texttt{primary\_conds : var\_id $\to$ val}.  Conditions on
                derived variables are discarded.
          \item For each primary variable $v$:
                \begin{itemize}
                  \item If $v$ does not appear in \texttt{primary\_conds},
                        set all entries of \texttt{compatible\_values[v]} to
                        \texttt{true} (all values of $v$ are compatible via
                        this rule).
                  \item If $v$ appears in \texttt{primary\_conds} with value
                        $c$, set \texttt{compatible\_values[v][c]} to
                        \texttt{true} (only value $c$ is compatible via this
                        rule).
                \end{itemize}
        \end{enumerate}
\end{enumerate}

Because entries are only ever set from \texttt{false} to \texttt{true} (never
the reverse), the final array is the union of compatible values across all
rules — exactly the projection of $S_d$.

\paragraph{Placement.}  The class lives in
\texttt{src/search/merge\_and\_shrink/} rather than alongside the general
\texttt{axioms.cc} infrastructure.  This keeps M\&S-specific logic contained
within the M\&S module, avoiding unnecessary coupling to components that use
\texttt{AxiomEvaluator} for unrelated purposes (state generation, root task
initialisation, etc.).  The file is registered in the \texttt{mas\_heuristic}
library in \texttt{src/search/CMakeLists.txt}.

\subsubsection{Example}

Consider a task with primary variables $x \in \{0,1,2\}$ and $y \in \{0,1\}$,
and two axiom rules for derived variable $d$:

\begin{itemize}
  \item Rule 1: $d = \text{true} \leftarrow x = 1$
  \item Rule 2: $d = \text{true} \leftarrow x = 2 \wedge y = 0$
\end{itemize}

After scanning Rule~1 (condition only on $x = 1$):
\[
  \texttt{compatible\_values}[x] = [\texttt{false},\, \texttt{true},\, \texttt{false}],
  \quad
  \texttt{compatible\_values}[y] = [\texttt{true},\, \texttt{true}]
\]
(Rule~1 has no condition on $y$, so all values of $y$ become compatible.)

After scanning Rule~2 (conditions $x = 2$ and $y = 0$):
\[
  \texttt{compatible\_values}[x] = [\texttt{false},\, \texttt{true},\, \texttt{true}],
  \quad
  \texttt{compatible\_values}[y] = [\texttt{true},\, \texttt{true}]
\]

The final result says: values $x=1$ and $x=2$ are compatible with $d$ being
true; $x=0$ is not.  All values of $y$ are compatible (because Rule~1 already
made $y$ fully compatible in the first scan).

\subsection{Step 2 — Implement the $(\cdot)^A$ Transformation}
\textbf{File modified:} \texttt{merge\_and\_shrink/fts\_factory.cc}

\subsubsection{The Transformation}

Currently, goal states in an atomic transition system are determined solely by
primary goal conditions.  A variable $v$ that does not appear in the primary
goal has all its values marked as goal states (it is unconstrained).  A
variable $v$ that does appear in the primary goal has exactly one goal value.

Under the $(\cdot)^A$ transformation, a local state $s \in A(V_S)$ becomes a
goal state if there \emph{exists} some completion of $V \setminus V_S$ such
that the resulting global state lies in $S_d$:

\[
  s \models (\cdot)^A
  \;\iff\;
  \exists\, \sigma_{V \setminus V_S} :\;
  \bigl(s \cup \sigma_{V \setminus V_S}\bigr) \in S_d.
\]

For an atomic factor over primary variable $v$, each value $v = c$ is marked
as a goal state whenever \emph{any} global state with $v = c$ belongs to
$S_d$, i.e., whenever \texttt{PrimaryRepresentation(d).is\_compatible(v, c)}
is true.  This is the existential projection of $S_d$ onto $v$'s domain,
which is exactly what \texttt{PrimaryRepresentation} computes from Step~1.

The transformation is applied to \emph{primary} variables only.  For derived
variables the goal state is determined by the derived variable's own goal
value (if it appears in the goal) or is unconstrained (all states are goal
states, if it does not).

\subsubsection{Why This Is Safe}

The projection is conservative: if a global state $s$ satisfies $d$ (i.e.,
$s \in S_d$), then for every primary variable $v$, $s[v]$ is compatible with
$d$, so $s[v]$ will be marked as a goal state in the atomic factor for $v$.
No reachable goal state is ever missed.  The reverse may not hold: some marked
values may not actually lie in any global goal state, but this only causes the
heuristic to underestimate — it cannot violate admissibility.

\subsubsection{Implementation in \texttt{fts\_factory.cc}}

The factory class \texttt{FTSFactory} builds one atomic transition system per
planning variable.  Goal state marking is handled in two methods:
\texttt{initialize\_transition\_system\_data} (which orchestrates the
per-variable setup) and \texttt{build\_state\_data} (which marks goal states
for a single variable).

\paragraph{Change 1 — New include.}
Add \texttt{\#include "primary\_representation.h"} so that
\texttt{FTSFactory} can instantiate \texttt{PrimaryRepresentation} objects.

\paragraph{Change 2 — Updated method declaration.}
The declaration of \texttt{build\_state\_data} inside the \texttt{FTSFactory}
class gains a second parameter: a \texttt{const} reference to a vector of
\texttt{PrimaryRepresentation} objects, one per derived goal variable.

\paragraph{Change 3 — Modified \texttt{build\_state\_data}.}
The original goal-state marking loop sets every value to \texttt{true} if the
variable has no primary goal condition, or sets only the goal value to
\texttt{true} otherwise.  The modified version adds a second condition for
primary variables: a value also passes only if it is compatible with every
derived goal variable according to its \texttt{PrimaryRepresentation}.  An
inner loop iterates over the precomputed representations; if any one of them
marks the value as incompatible, the value is excluded.  A value must be
compatible with \emph{all} derived goals simultaneously, because the goal is
a conjunction — this corresponds to the intersection of the individual
projections.  Derived variables bypass this loop entirely: their goal states
continue to be set solely by the standard goal-value check, since the
$(\cdot)^A$ transformation applies only to primary variable factors.

\paragraph{Change 4 — Modified \texttt{initialize\_transition\_system\_data}.}
Before iterating over variables to call \texttt{build\_state\_data}, one
\texttt{PrimaryRepresentation} is precomputed for each derived variable that
appears in the task goal.  These objects are constructed once and passed to
every call of \texttt{build\_state\_data}, avoiding repeated recomputation.
If the task has no derived goal variables (e.g., Miconic), the vector is
empty and the filter loop in \texttt{build\_state\_data} never executes —
existing behaviour is fully preserved.

\subsubsection{Behaviour on Tasks Without Axioms}

On any task without derived variables, \texttt{derived\_goal\_reprs} is
empty.  The new compatibility loop executes zero iterations for every value
of every variable, so \texttt{compatible} stays \texttt{true} throughout.
The resulting goal states are identical to those produced by the original
code.  Test~1 (Miconic) confirmed this: the planner produces the same plan
with the same heuristic values as before the change.

Atomic transition system \#31 (var31) is pruned to 0 states and the planner

operator transitions in the M\&S abstraction --- their value is determined by
axiom evaluation, not by operator effects.  With only value~0 (blocked) as a
goal state and no transitions that set the variable to value~0, the pruning
step removes all states as irrelevant (including the initial state), making
the factor unsolvable.

This is a known limitation of the current partial implementation.  Steps~3--5
will add axiom-induced abstract factors and handle derived variable
transitions properly, after which the heuristic will correctly reason about
derived goal satisfaction.

confirms that the (·)$^A$ filter correctly handles the over-approximation
case (all primary values remain compatible).  Pattern~3 confirms that goal
derived variables have their goal states correctly restricted to the goal
value.  The diagnostic block and the temporary removal of
\texttt{verify\_no\_axioms} were reverted after testing.

\subsection{Step 3 — Build Axiom-Induced Abstract Factors}
\textbf{New/modified files:}
\texttt{merge\_and\_shrink\_representation.h/.cc},
\texttt{factored\_transition\_system.h/.cc},
\texttt{fts\_factory.h/.cc}

After constructing the initial atomic factors, a preprocessing phase inserts
one additional factor $\Theta_{S,d}$ per derived goal variable $d$.  Unlike
the atomic factors, $\Theta_{S,d}$ spans multiple primary variables
simultaneously.  The reconstruction property guarantees that intersecting the
per-factor axiom languages with $\mathcal{L}(\Theta_{S,d})$ recovers the full
product's axiom language exactly.

\subsubsection*{How the implementation fulfils the original plan}

The original plan described four steps for building $\Theta_{S,d}$.  The
table below maps each step to the implementation piece that fulfils it.

\begin{center}

Implementing this step required three infrastructure pieces:
\begin{enumerate}
  \item A new \textbf{\texttt{MergeAndShrinkRepresentationProduct}} class
        (\S\ref{sec:piece1}) to represent the lookup table for a product-of-variables
        factor.
  \item A new \textbf{\texttt{FactoredTransitionSystem::add\_factor}} method
        (\S\ref{sec:piece2}) to inject a pre-built factor into the FTS after
        initial construction.
  \item A standalone \textbf{\texttt{build\_axiom\_factor}} function
        (\S\ref{sec:piece3}) that assembles all components of $\Theta_{S,d}$
        from the task proxy and calls \texttt{add\_factor}.
\end{enumerate}

\subsubsection{Piece 1: \texttt{MergeAndShrinkRepresentationProduct}}
\label{sec:piece1}

\paragraph{Motivation.}
The existing representation hierarchy has two concrete classes.
\texttt{MergeAndShrinkRepresentationLeaf} handles a single planning variable
via a flat array indexed by the variable's value.
\texttt{MergeAndShrinkRepresentationMerge} handles a recursively merged pair
of factors via a 2-D table indexed by the abstract states of the two children.
Neither class is suitable for $\Theta_{S,d}$: the factor spans an arbitrary
set of primary variables simultaneously, not a single variable and not a
recursive binary merge.

\paragraph{Mixed-radix encoding.}
Let the product variables be $x_0, x_1, \ldots, x_{n-1}$ with domain sizes
$d_0, d_1, \ldots, d_{n-1}$.  A combined assignment $(v_0, \ldots, v_{n-1})$
is encoded as the single integer
\[
  \mathrm{id} = \sum_{i=0}^{n-1} v_i \cdot m_i,
  \qquad
  m_0 = 1,\quad m_i = m_{i-1} \cdot d_{i-1}.
\]
The total number of product states is $\prod_i d_i$.  Decoding is
$v_i = \lfloor \mathrm{id} / m_i \rfloor \bmod d_i$.  The class stores
\texttt{var\_ids} (sorted variable IDs), \texttt{multipliers} ($m_i$ values),
and \texttt{lookup\_table} (flat vector of size $\prod d_i$), all computed
once at construction time.

\paragraph{Lookup table lifecycle.}
The table follows the same three-phase lifecycle as the existing classes.
After construction it holds the identity mapping (\texttt{lookup\_table[i] = i}).
After \texttt{apply\_abstraction\_to\_lookup\_table} each live entry is
remapped through the shrink strategy's output.  After \texttt{set\_distances}
each live entry is replaced by its goal distance.  Entries that are
\texttt{PRUNED\_STATE} are left unchanged throughout.

\paragraph{Constructor initialization order.}
The base class \texttt{MergeAndShrinkRepresentation} stores \texttt{domain\_size}.
In C++, base class subobjects are fully initialized before any derived-class
member is initialized.  The constructor therefore passes
\texttt{compute\_product\_size(var\_ids, domain\_sizes)} to the base class
first, then initializes \texttt{lookup\_table(domain\_size)}, which reads the
already-set \texttt{domain\_size} without a second traversal.

\subsubsection{Piece 2: \texttt{FactoredTransitionSystem::add\_factor}}
\label{sec:piece2}

\paragraph{Motivation.}
The \texttt{FactoredTransitionSystem} constructor receives all factors at once;
there is no existing method to inject a factor after construction.  For Step~3
we need to add $\Theta_{S,d}$ after the primary atomic factors have already
been built by \texttt{FTSFactory}.

\paragraph{Design.}
The method accepts a pre-built \texttt{TransitionSystem} and
\texttt{MergeAndShrinkRepresentation}.  The \texttt{Distances} object is
\emph{not} accepted from the caller; instead it is created internally from the
new transition system, mirroring the pattern used by \texttt{merge()}.
Distances are computed immediately after the factor is appended, preserving the
FTS invariant that all active factors always have up-to-date distances.  The
active entry count is incremented by one, in contrast to \texttt{merge()},
which replaces two factors with one and therefore decrements the count.

\subsubsection{Piece 3: \texttt{build\_axiom\_factor}}
\label{sec:piece3}

\texttt{build\_axiom\_factor} is a free function declared in
\texttt{fts\_factory.h} and implemented in \texttt{fts\_factory.cc}.  It must
be called \emph{before} any M\&S transformations, so that all label IDs still
correspond one-to-one to planning operators.  The function assembles
$\Theta_{S,d}$ in seven steps.

\paragraph{Step 1 — Identifying the primary variables ($S_d$).}
The function iterates over all axioms.  For each axiom whose head is $d$, it
collects the IDs of all primary (non-derived) variables that appear in the
body.  The union across all axioms for $d$ is $S_d$.  The result is a sorted,
duplicate-free vector \texttt{var\_ids}; a hash map
\texttt{var\_id\_to\_idx} provides $O(1)$ reverse lookup.

\paragraph{Step 2 — Domain sizes and multipliers.}
From \texttt{var\_ids} and the per-variable domain sizes, the function computes
the mixed-radix multipliers and the total number of product states.  A helper
lambda \texttt{decode\_val(s, i)} encodes the decoding formula and is reused
throughout the subsequent steps.

\paragraph{Step 3 — Initial state.}
The initial product state is encoded as
$\mathrm{init\_state} = \sum_i \mathrm{init}[x_i] \cdot m_i$.

\paragraph{Step 4 — Goal states (initial implementation).}
A product state $s$ is marked as a goal if it satisfies the primary
preconditions of at least one axiom body for $d$.  For each such axiom, the
function collects the required values of $S_d$ variables from the body, ignoring
any derived-variable preconditions.  All product states satisfying those
requirements are marked as goals.

Ignoring derived preconditions is a safe \emph{over-approximation}: more states
are marked as goals than strictly required, which can only cause the heuristic
to underestimate, preserving admissibility.

\emph{This approach was replaced by stratified forward chaining after testing
revealed it marked every product state as a goal, collapsing the factor to a
single abstract state ($h = 0$ everywhere).  See the ``Informativeness gap''
paragraph in the testing section below for the corrected implementation.}

\paragraph{Step 5 — Transitions for each operator label.}
An operator is \emph{relevant} to the product factor if it has a precondition or
effect on at least one variable in $S_d$.  For each relevant operator, the
function enumerates all product states, checks applicability (operator
preconditions on $S_d$ variables), and computes the target state by applying
each effect on an $S_d$ variable:
\[
  t = s - v_i^{(t)} \cdot m_i + \mathrm{post}_i \cdot m_i,
\]
where $v_i^{(t)}$ is decoded from the \emph{current} $t$ (not from $s$), so
that multiple effects on the same variable are handled correctly.

Two sub-cases arise for conditional effects:
\begin{itemize}
  \item \textbf{Condition on the same variable:} if the condition requires a
        specific value that $s$ does not have, the effect definitely does not
        fire for this product state and is skipped.
  \item \textbf{Condition on another variable:} the condition cannot be
        evaluated from the product state.  The effect is assumed to fire
        (producing the forward transition $s \to t$), and a self-loop $s \to s$
        is also added to model the case where the condition is not met.  This is
        again a safe over-approximation.
\end{itemize}
A known limitation at the time of writing (later fixed in Step~9): when an
operator has multiple effects on \emph{different} $S_d$ variables, each
conditioned on a different variable outside $S_d$, only the ``all fire'' and
``none fire'' combinations were modelled.  The partial-firing combinations
were missing, under-approximating the transition relation and breaking
admissibility.  See \S\ref{sec:fix-b} for the fix and
\S\ref{sec:when-clause-theory} for the formal explanation of why
over-approximation is required.

\paragraph{Step 6 — Grouping into local labels.}
Labels (operators) with identical transition sets are grouped into a single
\texttt{LocalLabelInfo}, following the same algorithm as
\texttt{FTSFactory::build\_transitions\_for\_operator}.  All irrelevant operators
are grouped into a single self-loop local label, following
\texttt{FTSFactory::build\_transitions\_for\_irrelevant\_ops}.  The
\texttt{label\_to\_local\_label} mapping is sized to
\texttt{labels.get\_max\_num\_labels()} (not the current label count) to match
the convention used throughout \texttt{FTSFactory}, which reserves space for
labels created by future label-reduction steps.

\paragraph{Step 7 — Construction and injection.}
A \texttt{TransitionSystem} is constructed from the assembled components.  The
\texttt{incorporated\_variables} field is set to \texttt{var\_ids}, recording
which primary variables contributed to this factor.  A
\texttt{MergeAndShrinkRepresentationProduct} is constructed from \texttt{var\_ids}
and the per-variable domain sizes.  Both are passed to \texttt{fts.add\_factor},
which creates \texttt{Distances} internally, computes distances immediately, and
returns the index of the new factor.

\subsubsection{Piece 4: Algorithm Integration in \texttt{merge\_and\_shrink\_algorithm.cc}}
\label{sec:piece4}

This piece connects \texttt{build\_axiom\_factor} to the main M\&S algorithm.
It makes four targeted changes to \texttt{merge\_and\_shrink\_algorithm.cc}.

\paragraph{Change 1 — Remove the axiom abort.}
\texttt{task\_properties::verify\_no\_axioms(task\_proxy)} is commented out.
This single call was the only reason tasks with derived variables were rejected.
With Pieces~1--3 in place, derived goal variables are handled correctly.

\paragraph{Change 2 — Add include.}
\texttt{\#include "shrink\_quasi\_bisimulation.h"} is added so that
\texttt{ShrinkQuasiBisimulation} is available in the new axiom factor loop.

\paragraph{Change 3 — Detect derived goals and extend \texttt{compute\_goal\_distances}.}
A boolean \texttt{has\_derived\_goals} is computed by scanning
\texttt{task\_proxy.get\_goals()} for variables where \texttt{is\_derived()} is
true.  This flag is OR'd into the existing \texttt{compute\_goal\_distances}
condition.  The extension is necessary because
\texttt{ShrinkQuasiBisimulation::requires\_goal\_distances()} returns true:
goal distances must be available in the new factor before shrinking can be
applied.  Without this change, \texttt{add\_factor} might initialise distances
with \texttt{compute\_goal\_distances = false}, leaving goal distances
uninitialised when \texttt{compute\_equivalence\_relation} is called later.

\paragraph{Change 4 — Build and shrink one axiom factor per derived goal variable.}
After \texttt{create\_factored\_transition\_system} returns and
\texttt{log\_progress} reports the atomic factors, the code enters an
\texttt{if (has\_derived\_goals)} block.  A single
\texttt{ShrinkQuasiBisimulation qbisim} is constructed once before the loop
and reused for all derived goal variables.  For each derived goal variable the
loop performs three operations:

\begin{enumerate}
  \item \texttt{build\_axiom\_factor(task\_proxy, derived\_var\_id, fts, log)}
        constructs $\Theta_{S,d}$, injects it into the FTS, and returns its
        index \texttt{axiom\_index}.
  \item \texttt{qbisim.compute\_equivalence\_relation} computes the
        quasi-bisimulation partition using the transition system and distances
        at \texttt{axiom\_index}, with \texttt{max\_states\_before\_merge} as
        the target size (the same size limit used when shrinking regular atomic
        factors before merging).
  \item \texttt{fts.apply\_abstraction(axiom\_index, equiv, log)} applies the
        partition to shrink the factor in place.
\end{enumerate}

\paragraph{Placement constraint.}
The loop is inserted after
\texttt{log\_progress(timer, "after computation of atomic factors", log)}
and before the pruning loop (\texttt{bool pruned = false; bool unsolvable = false;}).
At this point all atomic factors exist and all label IDs still correspond
one-to-one to planning operators (label reduction has not run yet), which
satisfies the precondition stated in \S\ref{sec:piece3}.  The axiom factors
are therefore visible to the merge strategy from the very start of the main
loop, and the full label space is available for the transition grouping done
inside \texttt{build\_axiom\_factor}.

\subsubsection{Testing on the Philosophers Domain}

After implementing Pieces~1--4, the planner was run on the Philosophers
benchmark (\texttt{p01-phil2.pddl}, 2~philosophers) with the standard M\&S
configuration.  Two bugs were discovered and fixed.

\paragraph{Bug 1 — Unsolvable atomic factor for derived goal variables.}\hypertarget{par:step3-bug1}{}
\textbf{Symptom:} The planner immediately reported
\texttt{Atomic FTS is unsolvable, stopping computation} and returned
\texttt{infinity} for the initial heuristic value.

\textbf{Root cause:} In \texttt{FTSFactory::build\_state\_data}, the goal
value for each variable was set from the planning task goal.  For derived
goal variables (e.g.\ \texttt{blocked philosopher-0}, var31, with goal
value~0 = ``blocked''), only value~0 was marked as a goal state.  But derived
variables have \emph{no operator transitions} --- their value is determined
by axiom evaluation, not by operator effects.  The atomic factor for var31
therefore had no transition from the initial state (value~1, ``not blocked'')
to the goal state (value~0), making the factor provably unsolvable.  The
pruning step then marked the entire task as unsolvable.

\textbf{Fix:} In \texttt{FTSFactory::build\_state\_data}
(\texttt{fts\_factory.cc}), immediately after the goal value is read from the
task goal, add:

\begin{lstlisting}[language=C++]
// Derived variables have no operator transitions; their goal condition is
// fully encoded in the axiom factor Theta_{S,d}. Mark all states as goals so
// the atomic factor does not falsely declare the task unsolvable.
if (var.is_derived())
    goal_value = -1;
\end{lstlisting}

Setting \texttt{goal\_value = -1} causes the loop below to mark all states as
goal states, making the atomic factor for derived variables unconstrained.
The actual goal constraint for a derived variable is encoded entirely in its
axiom factor $\Theta_{S,d}$.

\paragraph{Bug 2 — Assertion failure in \texttt{MergeScoringFunctionTotalOrder}.}
\textbf{Symptom:} The planner crashed mid-run with:
\begin{lstlisting}
Assertion `scores.size() == candidate_index + 1' failed.
\end{lstlisting}
at \texttt{merge\_scoring\_function\_total\_order.cc:55}.

\textbf{Root cause:} \texttt{MergeScoringFunctionTotalOrder::initialize}
precomputes a total order over all merge candidates.  It assumed
\texttt{num\_variables} initial factors (indices $0 \ldots N-1$) and product
TS indices in the range $[N,\, 2N-2]$.  With two axiom factors injected at
indices $N$ and $N+1$, the product TSes created during the main loop received
indices starting at $N+2$ instead of $N$.  The last two product TSes therefore
got indices $2N$ and $2N+1$, which were outside the precomputed range.  When
the merge selector tried to score a candidate pair involving those indices, the
loop found no match in \texttt{merge\_candidate\_order}, pushed no score, and
the assertion fired.

\textbf{Fix:} In \texttt{MergeScoringFunctionTotalOrder::initialize}
(\texttt{merge\_scoring\_function\_total\_order.cc}), count the number of
axiom factors (one per derived goal variable) before building the order, and
replace \texttt{num\_variables} with \texttt{num\_initial\_factors}
$= \texttt{num\_variables} + \texttt{num\_axiom\_factors}$ throughout:

\begin{lstlisting}[language=C++]
int num_axiom_factors = 0;
for (FactProxy goal : task_proxy.get_goals())
    if (goal.get_variable().is_derived())
        ++num_axiom_factors;
int num_initial_factors = num_variables + num_axiom_factors;
int max_transition_system_count = num_initial_factors * 2 - 1;
\end{lstlisting}

The atomic TS range is extended to $[0,\, \texttt{num\_initial\_factors} - 1]$
(treating axiom factors as atomic factors for ordering purposes), and the
product TS range is shifted to
$[\texttt{num\_initial\_factors},\, \texttt{max\_transition\_system\_count} - 1]$.
Tasks without axioms are unaffected: \texttt{num\_axiom\_factors} $= 0$ gives
the original behaviour.

\paragraph{Result after both fixes.}
The M\&S algorithm ran to completion: 39 initial factors (37 atomic + 2~axiom),
38 merges, 1~remaining factor.  The algorithm log showed the two axiom factors
being built and shrunk before the main loop, as intended.  However, the initial
heuristic value was~0 and the planner reported no solution, even though running
\texttt{astar(blind())} on the same instance found a plan of length~18.

\paragraph{Bug 3 — \texttt{prune\_unreachable\_states} incorrectly prunes derived variable states.}

\textbf{Root cause.}
The ``no solution'' outcome is caused by inadmissibility introduced by
\texttt{prune\_unreachable\_states}, not by the heuristic returning $h = 0$
everywhere.  To see why, consider the atomic transition system for the derived
variable \texttt{blocked philosopher-0} (var31).  This variable has domain
$\{0 = \textit{blocked}, 1 = \textit{not-blocked}\}$ and initial value
$1$ (not blocked).  No \emph{operator} has an effect on var31; its value is
set entirely by axiom evaluation at run time.

Because no operator changes var31, the standard forward BFS from the initial
state (value $= 1$) finds only state~1 reachable via operator transitions.
State~0 (\texttt{blocked~= true}) has $\texttt{init\_distance} = \infty$ and
is therefore pruned by \texttt{prune\_unreachable\_states}.  The look-up table
for the leaf representation of var31 becomes:
\[
  \texttt{lookup}[0] = \texttt{PRUNED\_STATE},\quad
  \texttt{lookup}[1] = 0.
\]
This makes \texttt{is\_total()} return \texttt{false}, so the factor is \emph{not}
classified as trivial and is retained in \texttt{mas\_representations}.

\textbf{Consequence during search.}
Whenever axiom evaluation sets \texttt{blocked philosopher-0 = 0} (i.e., the
philosopher \emph{is} actually blocked in the current state),
\texttt{get\_value} returns \texttt{PRUNED\_STATE}, and
\texttt{compute\_heuristic} returns \texttt{DEAD\_END}.  Because the goal
requires \texttt{blocked philosopher-0 = 0} (and likewise for
\texttt{philosopher-1}), every goal state evaluates to \texttt{DEAD\_END}.
Moreover, every state on any solution path where one philosopher has already
become blocked while the other has not yet done so also evaluates to
\texttt{DEAD\_END}, since axiom evaluation there sets var31 to~0.  As a
result, $A^*$ never accepts any goal state and reports ``no solution''.

\textbf{Fix.}
Skip \texttt{prune\_unreachable\_states} for derived variable atomic factors in
the pruning loop of \texttt{MergeAndShrinkAlgorithm::build\_factored\_transition\_system}
(file \texttt{merge\_and\_shrink\_algorithm.cc}).  Derived variable values are
determined at run time by axiom evaluation, not by operator reachability, so
the forward-reachability criterion is unsound for them.  The fix:

\begin{lstlisting}[caption={Skip unreachable-state pruning for derived variable factors}]
int num_variables = task_proxy.get_variables().size();
bool pruned = false;
bool unsolvable = false;
for (int index = 0; index < fts.get_size(); ++index) {
    assert(fts.is_active(index));
    // Derived variable atomic factors: skip prune_unreachable_states.
    // Their values are set by axiom evaluation, not by operator
    // transitions, so forward reachability from the init state is
    // unsound: non-init values can appear in any reachable planning state.
    bool effective_prune_unreachable = prune_unreachable_states &&
        !(index < num_variables &&
          task_proxy.get_variables()[index].is_derived());
    if (effective_prune_unreachable || prune_irrelevant_states) {
        bool pruned_factor = prune_step(
            fts, index,
            effective_prune_unreachable, prune_irrelevant_states,
            log);
        pruned = pruned || pruned_factor;
    }
    if (!fts.is_factor_solvable(index)) { ... }
}
\end{lstlisting}

After this fix, all states of every derived variable atomic factor remain live.
Since all states were already marked as goals (by the earlier fix that sets
\texttt{goal\_value = -1} for derived variables), every derived variable factor
is now trivial — its look-up table is all zeros — and is excluded from
\texttt{mas\_representations}.  The heuristic therefore returns $h = 0$
for all states, which is \emph{admissible} (though uninformative).

\paragraph{Secondary bug — \texttt{PrimaryRepresentation} uses wrong axiom API.}
In \texttt{primary\_representation.cc}, the constructor iterates over
\texttt{axiom.get\_preconditions()} to collect the axiom body conditions on
primary variables.  However, in FD's grounded SAS+ representation,
\texttt{axiom.get\_preconditions()} does \emph{not} return the body conditions:
it returns only the single ``prevVal'' fact — the value that the derived
variable must hold \emph{before} the axiom fires (used to implement
negation-by-failure semantics at the operator level).  The actual body
conditions of the axiom are stored as \emph{effect conditions} on the single
\texttt{EffectProxy}, accessed via \texttt{axiom.get\_effects()[0].get\_conditions()}.
Using \texttt{axiom.get\_preconditions()} therefore reads only the prevVal —
one fact whose variable is the derived variable itself — so
\texttt{primary\_conds} is populated with irrelevant data and every primary
variable value is incorrectly marked compatible.  The $({\cdot})^A$
transformation becomes a no-op.

The fix is a one-line change:
\begin{lstlisting}[caption={Fix PrimaryRepresentation to use effect conditions for axiom body}]
// WRONG (returns only the prevVal of the derived variable, not the body):
for (FactProxy cond : axiom.get_preconditions()) { ... }

// CORRECT (returns the actual axiom body conditions):
for (FactProxy cond : axiom.get_effects()[0].get_conditions()) { ... }
\end{lstlisting}
After this fix, primary variable values that appear as conditions in no axiom
body for $d$ will not be marked compatible with $d$'s goal being achievable.

\paragraph{Transitive BFS implementation in \texttt{build\_axiom\_factor}.}

The remaining limitation was addressed by extending Step~1 of
\texttt{build\_axiom\_factor} to collect primary variables \emph{transitively}
via a breadth-first search over the derived-variable dependency graph.  Instead
of scanning only the axioms for $d$ directly, the function initialises a FIFO
queue with $d$ itself and a \texttt{visited\_derived} set containing $\{d\}$,
then iterates:

\begin{enumerate}
  \item Pop a derived variable $d'$ from the queue.
  \item Scan all axioms whose single effect variable is $d'$.
  \item For each condition in the axiom body (obtained via
        \texttt{axiom.get\_effects()[0].get\_conditions()}):
    \begin{itemize}
      \item If the condition is on a \emph{primary} variable, add it to the
            primary variable set $S_d$ (via \texttt{primary\_var\_set}).
      \item If the condition is on a \emph{derived} variable $d''$ not yet
            in \texttt{visited\_derived}, insert $d''$ into
            \texttt{visited\_derived} and push it onto the queue.
    \end{itemize}
\end{enumerate}

The BFS terminates when the queue is empty.  The union of all primary variables
encountered is $S_d$; the union of all derived variables encountered (including
$d$ itself) is the full transitive closure of $d$'s derived dependencies.

Note: in Fast Downward's grounded SAS+ representation, each axiom has exactly
one effect (stored as a single \texttt{EffectProxy}).  The body conditions are
stored as \emph{effect conditions} on that effect, accessed via
\texttt{axiom.get\_effects()[0].get\_conditions()}.  The field
\texttt{axiom.get\_preconditions()} holds only the prevVal (the value the
derived variable must have before the rule fires) and must \emph{not} be used
to read body conditions.

\paragraph{Bug 4 — \texttt{prune\_unreachable\_states} in the main loop incorrectly prunes merged factors containing derived variables.}

\textbf{Symptom.} Despite the trivial (and correct) axiom factors for
vars~31 and~36, the planner still reported ``no solution'' after the Bug~3
fix.  The heuristic trace patch revealed that \texttt{repr[0]} returned
\texttt{PRUNED\_STATE} for multiple states during the search, triggering
\texttt{DEAD\_END}.

\textbf{Root cause.} The census output showed that var2 (\texttt{var2},
\texttt{derived=1}) appears in the large main SCC
$[0, 7, 8, 9, 10, 2, 5, 11, 3, 12, 4, 1, 13, 14, 15, 16, 6]$.
This SCC is processed as a unit by the merge strategy: all variables in the
SCC are merged together during the main loop.  When var2 is incorporated into
a growing composite factor, the subsequent \texttt{prune\_unreachable\_states}
step runs a forward BFS from the initial abstract state over
\emph{operator} transitions.  Because no operator directly sets var2 (its
value is determined entirely by axiom evaluation), the BFS finds only abstract
states where var2 holds its initial value reachable.  All abstract states
where var2 has any other value receive $\texttt{init\_distance} = \infty$
and are pruned.

The lookup table for var2's component in the merged representation then maps
every non-initial value of var2 to \texttt{PRUNED\_STATE}.  During search,
whenever axiom evaluation sets var2 to a non-initial value — which happens in
reachable states on the solution path — \texttt{get\_value} returns
\texttt{PRUNED\_STATE} and \texttt{compute\_heuristic} returns \texttt{DEAD\_END}.

Bug~3's fix only protected the \emph{initial} pruning loop (the loop before
the main merge loop that prunes each atomic factor individually in
\texttt{build\_factored\_transition\_system}).  It did not protect the
\emph{per-merge} \texttt{prune\_step} call inside \texttt{main\_loop}, which
applies the same forward-reachability criterion to every newly created
composite factor.

\textbf{Fix.} Extend the Bug~3 logic to the main loop's per-merge pruning
step.  Immediately before calling \texttt{prune\_step} after each merge, check
whether the merged factor incorporates any derived variable by consulting
\texttt{get\_incorporated\_variables()}:

\begin{lstlisting}[language=C++, caption={Skip unreachable-state pruning for merged factors with derived variables}]
// Skip prune_unreachable_states for merged factors that incorporate
// derived variables: axioms set their values, not operators, so
// reachability analysis based on operators alone would incorrectly
// mark non-initial derived-variable values as unreachable.
bool merged_has_derived = false;
for (int v : fts.get_transition_system(merged_index)
                 .get_incorporated_variables()) {
    if (task_proxy.get_variables()[v].is_derived()) {
        merged_has_derived = true;
        break;
    }
}
bool effective_prune_unreachable =
    prune_unreachable_states && !merged_has_derived;
if (effective_prune_unreachable || prune_irrelevant_states) {
    bool pruned = prune_step(
        fts, merged_index, effective_prune_unreachable,
        prune_irrelevant_states, log);
\end{lstlisting}

The method \texttt{get\_incorporated\_variables()} returns all planning variable
IDs whose atomic factors have been merged into this composite factor.  If any
of them is derived, \texttt{prune\_unreachable\_states} is suppressed for this
merge step.  \texttt{prune\_irrelevant\_states} is unaffected: removing
dead-end states (states from which the goal is unreachable under operator
transitions) remains sound.

This fix is implemented in \texttt{main\_loop} of
\texttt{merge\_and\_shrink\_algorithm.cc}, in the \emph{Pruning} block
immediately after the merge step and before the \texttt{is\_factor\_solvable}
check.  The rest of the pruning block (log output, loop progress) is
unchanged.

\paragraph{Informativeness gap after API fix: \texttt{can\_derive} over-approximation.}

After applying the \texttt{get\_effects()[0].get\_conditions()} fix to both
\texttt{primary\_representation.cc} and the BFS in \texttt{fts\_factory.cc},
the BFS correctly identified $n = 8$ primary variables and built a 6480-state
product space.  However, the heuristic still returned $h = 0$ everywhere.

The root cause was in Step~4 of \texttt{build\_axiom\_factor}: the
\texttt{can\_derive} lambda that determines goal states.  The lambda recursively
checks whether axioms can set derived variable $d$ to value \texttt{target}
given product state $s$.  For derived conditions in the axiom body, it called
itself recursively.  But for the base case — when a derived variable has no
axiom that sets it to \texttt{target} — it returned \texttt{true} (treating the
target as achievable by default), which is the negation-by-failure default for
the case where \texttt{target} equals the variable's default value.

In the Philosophers domain, var36 (\texttt{blocked philosopher-0}) has goal
value~0 (blocked), which is the \emph{non-default} value.  Its five axioms each
have a condition on a different value of var5 (\texttt{at-process}) plus
conditions on intermediate derived variables.  The \texttt{can\_derive} lambda
ignored the derived conditions (treating them as always satisfied) and found
that for every value of var5 there existed some axiom that could fire — so
\emph{every} product state was marked as a goal.  With all 6480 states marked
as goals, quasi-bisimulation collapsed the factor to 1 state ($h = 0$
everywhere).

\paragraph{Fix: stratified forward chaining for goal-state marking.}

The \texttt{can\_derive} lambda was replaced with a precise evaluation loop
that performs \emph{stratified forward chaining} over the dependency closure.
For each product state $s$:

\begin{enumerate}
  \item Seed all derived variables in \texttt{visited\_derived} at their
        default values (\texttt{get\_default\_axiom\_value()}).
  \item Sort all relevant axioms by axiom layer.
  \item Iterate the sorted axioms in order.  For each rule:
    \begin{itemize}
      \item If the rule's effect variable has already been set to a non-default
            value, skip it (each rule fires at most once).
      \item Check every body condition:
        \begin{itemize}
          \item Derived condition: look up the current value in the evolving
                \texttt{derived\_vals} array.
          \item Primary condition: decode from the mixed-radix product state $s$.
                If the variable is not in the product space, over-approximate
                as satisfied.
        \end{itemize}
      \item If all conditions are met, set \texttt{derived\_vals[eff\_var]}
            to the rule's effect value.
    \end{itemize}
  \item Mark $s$ as a goal state iff
        \texttt{derived\_vals[derived\_var\_id] == goal\_derived\_value}.
\end{enumerate}

FD's stratification guarantee ensures that a single pass in layer order
suffices: there are no intra-layer positive cycles.

\begin{lstlisting}[language=C++, caption={Stratified forward chaining for goal-state marking (fts\_factory.cc)}]
// Default values for all derived variables in the dependency closure.
unordered_map<int, int> derived_default;
for (int d : visited_derived)
    derived_default[d] = variables[d].get_default_axiom_value();

struct AxiomRule {
    int layer, eff_var, eff_val;
    vector<pair<int, int>> conditions; // (var_id, required_value)
};
vector<AxiomRule> relevant_axioms;
for (OperatorProxy axiom : task_proxy.get_axioms()) {
    EffectProxy eff = axiom.get_effects()[0];
    int eff_var_id = eff.get_fact().get_variable().get_id();
    if (!visited_derived.count(eff_var_id)) continue;
    AxiomRule rule;
    rule.layer   = variables[eff_var_id].get_axiom_layer();
    rule.eff_var = eff_var_id;
    rule.eff_val = eff.get_fact().get_value();
    for (FactProxy cond : eff.get_conditions())
        rule.conditions.emplace_back(
            cond.get_variable().get_id(), cond.get_value());
    relevant_axioms.push_back(move(rule));
}
sort(relevant_axioms.begin(), relevant_axioms.end(),
     [](const AxiomRule &a, const AxiomRule &b) {
         return a.layer < b.layer;
     });

vector<int> derived_vals(variables.size());
vector<bool> goal_states(num_product_states, false);
for (int s = 0; s < num_product_states; ++s) {
    for (auto &[d, def] : derived_default)
        derived_vals[d] = def;

    for (const AxiomRule &rule : relevant_axioms) {
        if (derived_vals[rule.eff_var] != derived_default.at(rule.eff_var))
            continue;
        bool satisfied = true;
        for (auto [cvar, cval] : rule.conditions) {
            int cur_val;
            if (variables[cvar].is_derived()) {
                auto it = derived_default.find(cvar);
                cur_val = (it != derived_default.end())
                          ? derived_vals[cvar]
                          : variables[cvar].get_default_axiom_value();
            } else {
                auto it = var_id_to_idx.find(cvar);
                if (it == var_id_to_idx.end()) continue; // over-approximate
                cur_val = decode_val(s, it->second);
            }
            if (cur_val != cval) { satisfied = false; break; }
        }
        if (satisfied)
            derived_vals[rule.eff_var] = rule.eff_val;
    }
    goal_states[s] = (derived_vals[derived_var_id] == goal_derived_value);
}
\end{lstlisting}

\paragraph{Bug 5 — (·)$^A$ goal restriction on primary variable factors causes false dead ends.}

After confirming admissibility on p01, theoretical analysis revealed a latent
admissibility violation in the (·)$^A$ goal-state restriction that had been applied
to primary variable atomic factors via \texttt{PrimaryRepresentation}.

The restriction marks a primary variable value $v = c$ as a non-goal state in the
atomic factor for $v$ whenever $c$ is incompatible with some derived goal variable.
While sound as a restriction on \emph{final} goal states, it interacts badly with
\texttt{prune\_irrelevant\_states}: the pruning step removes every abstract state
whose goal distance is~$\infty$, which includes states with ``incompatible'' values
that nonetheless have operator transitions leading to compatible (and therefore
relevant) states.  Such states are valid intermediate states on solution paths; pruning
them produces false dead ends and violates admissibility.

\textbf{Fix.}  The (·)$^A$ filter is removed from \texttt{build\_state\_data}
entirely.  Primary variables with no explicit goal condition keep all their values as
goal states, matching the standard Fast Downward behaviour.  The
\texttt{derived\_goal\_reprs} parameter of \texttt{build\_state\_data} and the
corresponding \texttt{PrimaryRepresentation} precomputation in
\texttt{initialize\_transition\_system\_data} are also removed as they became unused.

Admissibility and informativeness are fully preserved: the axiom factors
$\Theta_{S,d}$ already encode all derived-goal reachability information; restricting
primary variable factors further is both redundant and harmful.

\subsection{Step 4 — Quasi-Bisimulation Shrinking}
\textbf{New files:} \texttt{merge\_and\_shrink/shrink\_quasi\_bisimulation.h},
\texttt{merge\_and\_shrink/shrink\_quasi\_bisimulation.cc}

\texttt{feature/axioms-in-ms}.

\subsubsection{Motivation: Why Standard Bisimulation Is Too Fine}

The standard bisimulation shrink strategy partitions states based on their
transition behaviour: two states are equivalent only if they have the same
goal distance and their outgoing transitions lead to equivalent states under
every label.  In particular, a state with \emph{no} outgoing transition under
label $\ell$ is never equivalent to a state that does have an $\ell$-transition
--- the two states always end up in different partitions, regardless of any
other similarity they may share.

This is too restrictive for the auxiliary transition systems $\Theta_{S,d}$
that will be constructed in Step~3.  In $\Theta_{S,d}$, the derived variable
$d$ has no operator transitions of its own: its value is determined by axiom
evaluation, not by explicit operator effects.  Many states in $\Theta_{S,d}$
will therefore naturally lack transitions under labels that primary-variable
states do have.  Standard bisimulation would split these transition-free states
into their own partitions, producing an unnecessarily large abstract factor.
Quasi-bisimulation avoids this by explicitly permitting a state to lack a
transition under a label without being distinguished from states that do have it.

\subsubsection{Quasi-Bisimulation: Formal Definition}

A relation $\sim_Q$ on the states of a transition system is a
\emph{quasi-bisimulation} if it satisfies both of the following conditions:

\begin{description}
  \item[QBISIM1] $s_1 \sim_Q s_2 \;\Rightarrow\; (s_1 \in S_G \iff s_2 \in S_G)$

  Equivalent states must agree on goal membership.  This is identical to the
  corresponding condition in standard bisimulation and ensures that the
  heuristic value is the same for both states.

  \item[QBISIM2] If $s_1 \sim_Q s_2$ and $s_1 \xrightarrow{\ell} t_1$, then
  either $s_2$ has no outgoing $\ell$-transition at all, or there exists $t_2$
  such that $s_2 \xrightarrow{\ell} t_2$ and $t_1 \sim_Q t_2$.

  If $s_1$ has an $\ell$-transition, then $s_2$ is not required to have one.
  But if $s_2$ \emph{does} have an $\ell$-transition, it must lead to a
  state equivalent to $t_1$.
\end{description}

Compared with standard bisimulation, QBISIM2 adds the alternative ``$s_2$ has
no $\ell$-transition at all''.  Standard bisimulation requires every
$\ell$-transition of $s_1$ to be matched by an $\ell$-transition of $s_2$,
with no exceptions.  Quasi-bisimulation is therefore a \emph{coarser}
equivalence: every standard bisimulation is a valid quasi-bisimulation (by
always choosing the matching-transition alternative), but not vice versa.  A
coarser equivalence means fewer equivalence classes and a smaller abstract
factor.

\subsubsection{The Signature-Based Algorithm}

The implementation in \texttt{ShrinkQuasiBisimulation} mirrors the structure
of \texttt{ShrinkBisimulation} exactly, except in phase~1 of the refinement
loop (the signature computation step), which is described in the next
subsubsection \emph{Implementing QBISIM2: The Wildcard Mechanism}.  Both strategies use iterative signature refinement: in each round,
states are partitioned by a compact representation of their outgoing transition
behaviour, and groups that were indistinguishable in the previous round are
split if their members now disagree.  The algorithm converges when no further
split can be made (stable fixpoint) or when splitting would exceed
\texttt{target\_size}.

\paragraph{Data structures.}
Each state is represented by a \texttt{Signature} record with four fields:
\begin{itemize}
  \item \texttt{h\_and\_goal}: the goal distance ($-1$ for goal states, the
    actual $h$ value for non-goal states, and a large constant for dead-end
    states).  Goal states sort before all non-goal states, which enforces
    QBISIM1.
  \item \texttt{group}: the current partition group of the state.
  \item \texttt{succ\_signature}: a sorted, deduplicated list of
    (label-group-id, target-group-id) pairs that encodes which label groups
    lead to which groups of successors.
  \item \texttt{state}: the original state index, used as a tie-breaker to
    make the ordering total.
\end{itemize}

The successor signature (\texttt{SuccessorSignature}) is the key field.  Two
states with the same \texttt{h\_and\_goal}, the same \texttt{group}, and the
same \texttt{succ\_signature} are indistinguishable and will not be split in
this round.

Two sentinel records are added at the start and end of the signatures array
before sorting.  They use special \texttt{h\_and\_goal} values that fall
outside the range of real states, allowing the main loop to detect block
boundaries without explicit bounds checks.  Dead-end states (goal distance
$\infty$) are mapped to a large finite value (\texttt{IRRELEVANT}) that sorts
before the trailing sentinel.

\paragraph{Initialisation.}
The algorithm begins by partitioning states into groups based solely on goal
distance.  Goal states all go into group~0.  Non-goal states are grouped by
$h$-value: all states with $h = i$ form their own group, and dead-end states
form another.  This starting partition is sound because states with different
$h$-values can never be quasi-bisimilar (QBISIM1 would be violated immediately),
so distinguishing them upfront saves refinement work.

\paragraph{Refinement loop.}
Each round consists of three phases:
\begin{enumerate}
  \item \textbf{Compute signatures.}  A fresh \texttt{Signature} is built for
    every state, filling in the \texttt{succ\_signature} field from the
    current transitions.  This is the step that differs from standard
    bisimulation; the modification is described in full in the next
    subsubsection.  After filling, each successor signature is sorted and
    deduplicated, then the entire signatures array is sorted.

  \item \textbf{Detect splits.}  Within each block of states sharing the same
    \texttt{h\_and\_goal} value, consecutive states with the same old group
    but different \texttt{succ\_signature} must be placed in different new
    groups.  The number of new groups is counted first; if splitting would
    exceed \texttt{target\_size}, the round is aborted immediately.

  \item \textbf{Apply splits.}  New group numbers are assigned.  The first
    subgroup of each old group retains the old group number; additional
    subgroups receive fresh numbers allocated in order.  Retaining the old
    group number for the first subgroup avoids renumbering the majority of
    states.
\end{enumerate}

\subsubsection{Implementing QBISIM2: The Wildcard Mechanism}

This is the only point where \texttt{ShrinkQuasiBisimulation} differs from
\texttt{ShrinkBisimulation}: it is a targeted modification to the first phase
of each refinement round (the signature computation step).

\paragraph{What standard bisimulation does.}
In standard bisimulation, a (label-group-id, target-group-id) entry is added
to a state's successor signature only when that state has an actual transition
under the label group.  A state with no outgoing $\ell$-transition contributes
no entry for $\ell$ to its signature.  After sorting, states without any
$\ell$-transition have a smaller (or shorter) signature than states with
$\ell$-transitions, so they sort separately and end up in a different partition.
This split is mandatory in standard bisimulation and happens unconditionally.

\paragraph{The wildcard entry.}
Quasi-bisimulation avoids this forced split by inserting a synthetic
\emph{wildcard} entry into the successor signature of every state that lacks
an $\ell$-transition, but only when at least one other state in the same
current group does have an $\ell$-transition.

The wildcard entry has the form $(\ell, g_{\min})$, where $\ell$ is used as
shorthand for the integer counter that the signature computation loop assigns
to label group $\ell$ (the variable \texttt{label\_group\_counter} in the
code, incremented once per label group).  This is the same integer that
appears as the first component of every real transition entry, so the wildcard
is formatted identically to a real entry.  $g_{\min}$ is the \emph{minimum
target-group ID} among all $\ell$-transitions that originate from any state in
the same current group.  After this entry is inserted, the no-transition
state's successor signature for label $\ell$ matches the signature of states
that transition to the group with ID $g_{\min}$.  When the signatures are
sorted, the no-transition state ends up adjacent to those states instead of in
its own separate partition.

\paragraph{Why the minimum target group?}
Using the minimum is a deterministic tie-breaking convention.  What matters is
that the no-transition state is given \emph{some} entry that matches at least
one subgroup of its current group, so that it is not split off into a partition
of its own.  The minimum is a natural choice because it corresponds to the
first subgroup (the one that retains the old group number when a split occurs),
it can be computed in a single pass over the transitions (by maintaining a
running minimum), and it is consistent with the convention used in the split
step.

If all states in a group have no $\ell$-transition, no wildcard is needed:
all their signatures agree on $\ell$ (they all have no entry for it), so no
$\ell$-induced split would occur regardless.  The wildcard mechanism therefore
only fires when there is a genuine mixed situation --- some states with
$\ell$-transitions, some without --- which is exactly the case that
quasi-bisimulation is meant to handle.

\paragraph{Tracking the minimum target group per source group.}
To determine which states need a wildcard and what value to insert, the
signature computation maintains two auxiliary data structures for each label
group $\ell$:
\begin{itemize}
  \item A per-state boolean flag indicating whether the state has at least
    one $\ell$-transition (after any skipped transitions are excluded).
  \item A map from source-group ID to the minimum target-group ID seen so far
    among $\ell$-transitions originating from that source group.
\end{itemize}
Both are built in a single pass over the transitions of $\ell$.  After that
pass, a second pass over all states checks the flag and the map: any state
without a transition whose group appears in the map receives the wildcard
entry.

\subsubsection{A Worked Example}

Consider a transition system with five states $\{s_0, s_1, s_2, s_3, s_4\}$
and a single label $\ell$.  Suppose at the start of a refinement round the
current partition is:
$G_0 = \{s_0, s_1\}$ (goal states, $h = 0$) and
$G_1 = \{s_2, s_3, s_4\}$ (non-goal, $h = 1$).
The outgoing $\ell$-transitions are:

\begin{center}
\begin{tabular}{cl}
\toprule
\textbf{State} & \textbf{$\ell$-successors} \\
\midrule
$s_2$ & $s_0$ (in $G_0$, id~0) \\
$s_3$ & $s_1$ (in $G_0$, id~0) \\
$s_4$ & none \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Standard bisimulation.}
Signature entries are added only for transitions that exist.  The successor
signatures for label $\ell$ are:
$\sigma(s_2) = [(\ell, 0)]$,
$\sigma(s_3) = [(\ell, 0)]$,
$\sigma(s_4) = [\,]$.
After sorting, $s_2$ and $s_3$ have identical signatures and stay together;
$s_4$ has a strictly smaller signature (empty list) and sorts into a separate
block.  Group $G_1$ is split into $\{s_2, s_3\}$ and $\{s_4\}$.

\paragraph{Quasi-bisimulation.}
During the transition scan for $\ell$: $s_2$ transitions to $s_0$ (target
group~0) and $s_3$ transitions to $s_1$ (target group~0).  Both transitions
land in group~0, so $g_{\min}(G_1) = \min(0, 0) = 0$.  State $s_4$ has no
$\ell$-transition, but its group $G_1$ contains states that do, so it receives
the wildcard entry $(\ell,\, g_{\min}) = (\ell, 0)$.

The wildcard value $g_{\min} = 0$ is the specific number that makes
$s_4$'s signature for label $\ell$ identical to those of $s_2$ and $s_3$.
Had we used any other value --- say $(\ell, 5)$ --- $s_4$'s signature would
differ from $s_2$'s and $s_3$'s, causing a spurious split.

To see the full role of $g_{\min}$, consider a variant where $s_3$ instead
transitions to a state in a \emph{different} group $G_2$ (id~2), while $s_2$
still transitions to $G_0$ (id~0).  Then $g_{\min}(G_1) = \min(0, 2) = 0$
and the signatures become:
$\sigma(s_2) = [(\ell, 0)]$,
$\sigma(s_3) = [(\ell, 2)]$,
$\sigma(s_4) = [(\ell, 0)]$.
Here $s_3$ splits off from $G_1$, while $s_4$ stays with $s_2$.  The minimum
determines which subgroup $s_4$ follows when a split happens: it always joins
the subgroup with the smallest target-group id --- the ``first'' subgroup to
emerge from $G_1$ under label $\ell$.

Returning to the original example, the successor signatures are:
$\sigma(s_2) = [(\ell, 0)]$,
$\sigma(s_3) = [(\ell, 0)]$,
$\sigma(s_4) = [(\ell, 0)]$.
All three are identical.  No split occurs; $G_1 = \{s_2, s_3, s_4\}$ remains
intact.

\paragraph{Correctness check (QBISIM2).}
Consider the pair $(s_2, s_4)$: $s_2 \sim_Q s_4$ (same group), and
$s_2 \xrightarrow{\ell} s_0$.  QBISIM2 requires that either $s_4$ has no
$\ell$-transition (which is true) or $s_4$ has an $\ell$-transition to some
state equivalent to $s_0$.  The first alternative holds, so QBISIM2 is
satisfied.  The same check applies to $(s_3, s_4)$.

The abstract factor now has two abstract states --- $[G_0]$ and
$[\{s_2,s_3,s_4\}]$ --- instead of three ($[G_0]$, $[\{s_2,s_3\}]$,
$[\{s_4\}]$), without any loss of admissibility.

\subsubsection{Correctness of the Wildcard Approach}

The wildcard mechanism produces a valid quasi-bisimulation.  The two conditions
are maintained as follows:
\begin{itemize}
  \item \textbf{QBISIM1} is identical to the corresponding condition in
    standard bisimulation: equivalent states must agree on goal membership.
    It is enforced by the initial partition (goal states in group~0, non-goal
    states by $h$-value) and by the fact that \texttt{h\_and\_goal} is the
    primary sort key in the signature comparison.  States with different goal
    status or different $h$-value are always placed in different groups and
    can never be merged in a later round.
  \item \textbf{QBISIM2} is enforced by the wildcard.  The argument is about
    the \emph{fixed-point} partition: when the algorithm terminates with no
    further splits, the resulting groups define the quasi-bisimulation relation.
    We must show that for any two states $s_1 \sim_Q s_2$ (same group at the
    fixed point) with $s_1 \xrightarrow{\ell} t_1$, QBISIM2 holds.  There are
    two cases depending on whether $s_2$ has an $\ell$-transition.

    \textbf{Case A: $s_2$ has an $\ell$-transition to $t_2$.}
    This case is identical to standard bisimulation.  Both $s_1$ and $s_2$
    receive real entries in their signatures: $({\ell}, \mathrm{group}(t_1))$
    for $s_1$ and $(\ell, \mathrm{group}(t_2))$ for $s_2$.  At the fixed
    point, the partition is stable --- no further splits would be made.  For
    $s_1$ and $s_2$ to remain in the same group, their signatures must be
    identical (if they differed, they would have been split in the last round).
    Therefore $\mathrm{group}(t_1) = \mathrm{group}(t_2)$, which means
    $t_1 \sim_Q t_2$.  The first alternative of QBISIM2 is satisfied:
    $s_2 \xrightarrow{\ell} t_2$ with $t_1 \sim_Q t_2$. \checkmark

    The entire difference between quasi-bisimulation and standard bisimulation
    lies in Case~B below.

    \textbf{Case B: $s_2$ has no $\ell$-transition.}
    The first question to answer is: how can $s_1$ and $s_2$ be in the same
    group at all in this situation?  In standard bisimulation, they cannot.
    $s_1$ has a real entry $(\ell, \mathrm{group}(t_1))$ in its signature;
    $s_2$ has no $\ell$-entry.  Their signatures differ, so they get split
    --- Case~B never arises under standard bisimulation.

    The wildcard changes this.  $s_2$ receives the synthetic entry
    $(\ell, g_{\min})$.  For $s_1$ and $s_2$ to have matching signatures ---
    and thus remain in the same group at the fixed point --- we need
    $\mathrm{group}(t_1) = g_{\min}$.  When this holds, the wildcard makes
    $s_2$'s $\ell$-entry identical to $s_1$'s real entry, and they can stay
    in the same group.  States whose $\ell$-transition leads to any other
    target group have a different entry and are split off in an earlier round.

    Once we establish that $s_1$ and $s_2$ can indeed be in the same group,
    QBISIM2 is satisfied by its second alternative: $s_2 \not\xrightarrow{\ell}$,
    which QBISIM2 explicitly permits. \checkmark

    In summary: the wildcard makes Case~B \emph{possible} (it gives $s_2$ an
    entry that can match $s_1$'s, keeping them together), and QBISIM2's
    second alternative makes it \emph{correct} (a state is not required to
    have a transition under $\ell$ just because its equivalent partner does).
    The two work together: the wildcard exploits the freedom that QBISIM2
    grants.
\end{itemize}

The algorithm does not guarantee the \emph{coarsest} quasi-bisimulation ---
no such coarsest relation is guaranteed to exist in general.  The result is a
valid quasi-bisimulation that is always at least as coarse as the standard
bisimulation computed by \texttt{ShrinkBisimulation}, and often strictly
coarser on tasks with derived variables.

\subsubsection{New Files and \texttt{CMakeLists.txt}}

The implementation lives in two new files:
\begin{itemize}
  \item \texttt{shrink\_quasi\_bisimulation.h} declares the class
    \texttt{ShrinkQuasiBisimulation}, a concrete subclass of
    \texttt{ShrinkStrategy}.  It forward-declares the internal
    \texttt{Signature} struct and exposes the same public interface as
    \texttt{ShrinkBisimulation}: \texttt{compute\_equivalence\_relation},
    \texttt{requires\_init\_distances} (false), and

\end{itemize}

The entry \texttt{merge\_and\_shrink/shrink\_quasi\_bisimulation} is added to

\paragraph{Safety analysis: \texttt{is\_factor\_solvable} in the initial pruning loop.}
During initial pruning (the loop at lines~\textasciitilde{}523--540 of
\texttt{merge\_and\_shrink\_algorithm.cc}), after calling \texttt{prune\_step}
for each factor, the algorithm checks
\begin{verbatim}
if (!fts.is_factor_solvable(index))
\end{verbatim}
and sets \texttt{unsolvable = true} if the factor is unsolvable.  This check is
applied uniformly to all factors, including axiom factors (indices $\geq$
\texttt{num\_variables}), without the \texttt{!is\_axiom\_factor} guard that
was added for Fix~1 in the main merge loop (line~395).

For solvable tasks, this check never triggers spuriously on axiom factors.  The
reasons are:
\begin{enumerate}
  \item Axiom factors are built with \texttt{prune\_unreachable\_states~=~false},
    so the abstract state corresponding to the concrete initial state is always
    present and is never marked as pruned.
  \item The goal is reachable from the initial state in any solvable task, so
    the init abstract state's goal distance is finite, and
    \texttt{is\_factor\_solvable} returns \texttt{true}.
\end{enumerate}
Together these guarantee that \texttt{is\_factor\_solvable} always returns
\texttt{true} for axiom factors on solvable tasks.  On a genuinely unsolvable
task the check correctly signals unsolvability.  A defensive
\texttt{!is\_axiom\_factor} guard was added at this location for additional
robustness (see below); it is not required for correctness but costs nothing.

\subsection{Step 6 --- A Merge-Order-Dependent Inadmissibility Bug}
\label{sec:step6}

\textbf{Files:} \texttt{merge\_and\_shrink\_algorithm.cc}, \texttt{utils.cc/.h},
\texttt{transition\_system.cc/.h}, \texttt{fts\_factory.cc},
new \texttt{merge\_scoring\_function\_axiom\_deferral.cc/.h}

After Steps~1--5 were validated against the table in \S\ref{sec:step5} (the
recommended configuration of \S\ref{sec:configexample}, which uses
\texttt{merge\_sccs}), the implementation was additionally tested with
\texttt{merge\_stateless} using \texttt{goal\_relevance} as the first scoring
function. On the same task (\texttt{phil01}, 2 philosophers, optimal cost~18)
this configuration incorrectly reported \emph{"Task is provably unsolvable"}.
This section documents the bug, the fix that was rejected, and the fix that
was adopted.

\subsubsection{Two Preliminary Fixes (Necessary but Not Sufficient)}

Two smaller bugs were found and fixed first, both in the pruning logic of the
main M\&S loop in \texttt{merge\_and\_shrink\_algorithm.cc}. Neither was
specific to a merge strategy, but both had to be fixed before the deeper,
merge-order-dependent bug could even be isolated.

\paragraph{Fix A --- \texttt{is\_axiom\_factor} guard in the initial pruning loop.}
At the point where the initial (atomic) factors are pruned, line~535
originally read
\begin{lstlisting}
if (!fts.is_factor_solvable(index)) { ... }
\end{lstlisting}
applied uniformly to every atomic factor, including axiom factors at indices
$\geq$ \texttt{num\_variables}. This was changed to
\begin{lstlisting}
if (!is_axiom_factor && !fts.is_factor_solvable(index)) { ... }
\end{lstlisting}
As argued above this guard is not strictly required for correctness on
solvable tasks, but it documents the intent and removes any doubt for
malformed or partially-pruned axiom factors.

\paragraph{Fix B --- \texttt{effective\_prune\_unreachable} missing the
\texttt{is\_axiom\_derived} guard in the main loop.}
The main loop tracks, for every factor index (including ones produced by
merging), whether that factor's information derives from an axiom factor:
\begin{lstlisting}
vector<bool> is_axiom_derived(fts.get_size(), false);
for (int i = num_variables; i < fts.get_size(); ++i)
    is_axiom_derived[i] = true;
// ... on every merge:
is_axiom_derived.push_back(
    is_axiom_derived[merge_index1] || is_axiom_derived[merge_index2]);
\end{lstlisting}
The pruning block after each merge originally computed
\begin{lstlisting}
bool effective_prune_unreachable =
    prune_unreachable_states && !merged_has_derived;
\end{lstlisting}
where \texttt{merged\_has\_derived} checks whether any variable in
\texttt{get\_incorporated\_variables()} is itself a derived variable. This
check is structurally always \texttt{false} for an axiom-derived merged
factor: \texttt{incorporated\_variables} for an axiom factor lists only the
\emph{primary} variables of $S_d$ (see \texttt{build\_axiom\_factor},
\S\ref{sec:piece3}), never the derived variable~$d$ itself. As a result,
\texttt{prune\_unreachable\_states} was firing unconditionally on
axiom-derived merged factors, even though backward/forward reachability
within a partial composite cannot soundly be used to prune states whose
relevance depends on variables not yet incorporated. The fix adds the same
guard already used for \texttt{effective\_prune\_irrelevant}:
\begin{lstlisting}
bool effective_prune_unreachable =
    prune_unreachable_states && !merged_has_derived
    && !is_axiom_derived[merged_index];
\end{lstlisting}
This was committed as \texttt{e703120c1}, ``Fix prune\_unreachable\_states and
is\_factor\_solvable for axiom-derived factors''. After this fix and Fix~A,
\texttt{merge\_sccs} continued to work, and the spurious-pruning log messages
disappeared from \texttt{merge\_stateless} runs too --- but \texttt{phil01}
was \emph{still} reported unsolvable under \texttt{merge\_stateless}. This
showed the remaining bug was not a pruning bug at all.

\subsubsection{Root Cause: Bisimulation Shrinking on a Partial Axiom-Derived Composite}
\label{sec:rootcause}

\texttt{build\_axiom\_factor} (\S\ref{sec:piece3}) constructs the axiom factor
$\Theta_{S,d}$ over the \emph{complete} primary-variable dependency set $S_d$,
computed once up front via a transitive BFS over the axiom-rule dependency
chain. The factor's goal states are computed by full stratified axiom
evaluation over this complete $S_d$. In isolation, $\Theta_{S,d}$ therefore
has exact, correct goal distances from the moment it is built --- the bug is
not in the axiom factor itself.

The bug appears once $\Theta_{S,d}$ is merged with other, unrelated
primary-variable factors during the main M\&S loop, \emph{before} all
variables that are needed to actually \emph{reach} the goal (via multi-step
operator sequences that change variables in $S_d$ through other
preconditions) have also been incorporated into the same composite factor.
\texttt{shrink\_before\_merge\_step} (\texttt{utils.cc}) is called on the two
factors chosen for the \emph{next} merge, \emph{before} that merge happens,
and it bisimulation-shrinks each of them using \texttt{Distances}, which
computes goal distances via a backward search restricted to that factor's
own (partial) transition system. Operators that only affect variables not
yet incorporated into the composite appear as self-loops on the axiom
component of the abstract state. If a concrete state can only reach the
derived goal through a path that requires one of those not-yet-incorporated
variables to change first, that path is invisible inside the partial
composite, and the composite's local goal distance for that abstract state
is (locally, validly) computed as $\infty$.

This is where the difference from an ordinary (non-axiom) M\&S factor
matters. For an ordinary factor, an abstract state's ``goal'' is simply the
projection of the task's real goal condition onto that factor's variables;
forgetting other variables can only ever make the abstraction's heuristic
value a (sound) \emph{underestimate}, because the abstraction is a strict
relaxation of the original problem. For an axiom-derived composite, by
contrast, bisimulation shrinking groups together every abstract state with
local distance $\infty$ into one equivalence class. Because the self-loops
on not-yet-incorporated variables never let the composite escape that class
as further merges happen, the $\infty$-distance label, once assigned, is
preserved by every subsequent merge --- right through to the single, final
factor used by the heuristic. The result is a finite, solvable concrete
state being assigned heuristic value $\infty$ (a ``dead end''), which is an
inadmissibility bug, not merely a performance loss.

\texttt{merge\_sccs} avoids triggering this bug on the Philosophers benchmark
because it clusters large strongly-connected components of \emph{primary}
variables together first (topological order), and only merges the
axiom-derived factor in once most or all of its surrounding context already
exists in the other side of the merge. \texttt{merge\_stateless} with
\texttt{goal\_relevance} as the first scoring function does the opposite: it
greedily picks the axiom factor for merging as early as possible (because it
is immediately goal-relevant), creating exactly the small, premature
composite that triggers the bug.

\subsubsection{Rejected Fix: Skip Shrinking Axiom-Derived Factors Entirely}

The first fix attempted was to make \texttt{shrink\_before\_merge\_step} skip
shrinking (i.e. skip the bisimulation-based distance computation entirely)
for whichever side of a merge candidate pair is axiom-derived:
\begin{lstlisting}
bool shrink_before_merge_step(
    FactoredTransitionSystem &fts, int index1, int index2, int max_states,
    int max_states_before_merge, int shrink_threshold_before_merge,
    const ShrinkStrategy &shrink_strategy, utils::LogProxy &log,
    bool skip_shrink1, bool skip_shrink2) {
    ...
    if (!skip_shrink1) { /* shrink index1 as before */ }
    if (!skip_shrink2) { /* shrink index2 as before */ }
    ...
}
\end{lstlisting}
called from the main loop with
\texttt{skip\_shrink1~=~is\_axiom\_derived[merge\_index1]},
\texttt{skip\_shrink2~=~is\_axiom\_derived[merge\_index2]}.

This is sound --- it removes every opportunity for the unsound partial
distance computation described in \S\ref{sec:rootcause} to occur, regardless
of merge order --- but it is impractical. Without bisimulation shrinking, an
axiom-derived factor accumulates states unshrunk through \emph{every}
subsequent merge step until it is finally combined with everything else.
On the Philosophers benchmark this caused uncontrolled growth of the
intermediate transition system; in practice the build/test process became
unresponsive (CLion froze and had to be force-closed) rather than completing
in reasonable time or memory. This fix was implemented, found impractical,
and reverted (never committed) in favour of the approach below.

\subsubsection{Adopted Fix: Defer Axiom-Derived Merges via a New Scoring Function}
\label{sec:axiomdeferral}

Rather than disabling shrinking, the adopted fix biases the \emph{merge
order} itself so that an axiom-derived factor is only ever merged once no
other candidate pair remains --- mirroring, in a strategy-agnostic way, what
\texttt{merge\_sccs} already does structurally for this benchmark. Shrinking
continues to run normally on every factor; the fix never lets an
axiom-derived factor be a candidate for merging while a same axiom-free
alternative still exists, so the premature small composite from
\S\ref{sec:rootcause} is never formed in the first place.

\paragraph{Tracking which factors are axiom-derived: \texttt{transition\_system.h/.cc}.}
A new boolean member is added to \texttt{TransitionSystem}:
\begin{lstlisting}
class TransitionSystem {
private:
    ...
    bool axiom_derived;
public:
    TransitionSystem(
        int num_variables, std::vector<int> &&incorporated_variables,
        const Labels &labels, std::vector<int> &&label_to_local_label,
        std::vector<LocalLabelInfo> &&local_label_infos, int num_states,
        std::vector<bool> &&goal_states, int init_state,
        bool axiom_derived = false);
    ...
    bool is_axiom_derived() const { return axiom_derived; }
};
\end{lstlisting}
The flag is set to \texttt{false} when atomic (primary-variable) factors are
constructed in \texttt{FTSFactory::create\_transition\_systems}, and to
\texttt{true} at the single construction site inside
\texttt{build\_axiom\_factor} (\S\ref{sec:piece3}). It is then propagated
through every subsequent merge: \texttt{TransitionSystem::merge} sets the
new factor's flag to \texttt{ts1.axiom\_derived || ts2.axiom\_derived}, so
the flag is transitively inherited by any composite that contains
axiom-derived information, exactly mirroring (at the \texttt{TransitionSystem}
level, rather than as a separate local vector) the \texttt{is\_axiom\_derived}
bookkeeping already done ad hoc inside the main loop for the pruning fixes
above.

\paragraph{New merge scoring function: \texttt{merge\_scoring\_function\_axiom\_deferral.h/.cc}.}
A new \texttt{MergeScoringFunction} subclass scores a merge candidate $0$
(best) if neither side is axiom-derived, and $1$ (worse) otherwise:
\begin{lstlisting}
vector<double> MergeScoringFunctionAxiomDeferral::compute_scores(
    const FactoredTransitionSystem &fts,
    const vector<pair<int, int>> &merge_candidates) {
    vector<double> scores;
    for (pair<int, int> merge_candidate : merge_candidates) {
        const TransitionSystem &ts1 =
            fts.get_transition_system(merge_candidate.first);
        const TransitionSystem &ts2 =
            fts.get_transition_system(merge_candidate.second);
        scores.push_back(
            (ts1.is_axiom_derived() || ts2.is_axiom_derived()) ? 1 : 0);
    }
    return scores;
}
\end{lstlisting}
Registered under the plugin name \texttt{axiom\_deferral}. Used as the
\emph{first} entry in a \texttt{score\_based\_filtering} scoring-function
list (\texttt{merge\_selector\_score\_based\_filtering.cc}, which filters
candidates iteratively, keeping only those tied for the best score at each
step), this guarantees that any candidate pair not touching an axiom-derived
factor is strictly preferred. Only once every remaining candidate touches an
axiom-derived factor does the filtering pass through to the next scoring
function (e.g.\ \texttt{goal\_relevance}), letting the axiom-derived merge
finally happen --- by which point the other side of the merge is typically
the single large composite of (almost) all primary variables, so the
resulting shrink is no longer operating on a small, premature partial
factor.

\paragraph{Files changed.} Committed as \texttt{1d7fa739a}:
\begin{itemize}
  \item \texttt{transition\_system.h}: add \texttt{axiom\_derived} member,
    constructor parameter, \texttt{is\_axiom\_derived()} accessor.
  \item \texttt{transition\_system.cc}: initialise the flag in both
    constructors; propagate via logical OR in \texttt{TransitionSystem::merge}.
  \item \texttt{fts\_factory.cc}: pass \texttt{false} at the atomic-factor

  \item new \texttt{merge\_and\_shrink/merge\_scoring\_function\_axiom\_deferral.h/.cc}.
  \item \texttt{CMakeLists.txt}: register the new source file.
\end{itemize}

\subsubsection{Validation}

With \texttt{axiom\_deferral} in place, \texttt{phil01} is solved correctly
and identically under both merge strategies:

\begin{center}
\begin{tabular}{lcccc}
\toprule
\textbf{Merge strategy} & \textbf{Init.\ $h$} & \textbf{Plan cost} & \textbf{Expanded} & \textbf{Dead ends} \\
\midrule
\texttt{merge\_sccs} (no \texttt{axiom\_deferral} needed) & 5 & 18 & 91 & 0 \\
\texttt{merge\_stateless} + \texttt{axiom\_deferral} & 5 & 18 & 91 & 0 \\
\bottomrule
\end{tabular}
\end{center}

The two configurations produce exactly the same heuristic value, expansion
count, plan cost, and (zero) dead ends on this instance, despite exploring
the merge order in a different sequence --- evidence that \texttt{axiom\_deferral}
restores admissibility for \texttt{merge\_stateless} without simply
happening to work around this particular benchmark by chance. The log of
the \texttt{merge\_stateless} run also confirms the deferral takes effect
as intended: the axiom-derived factors (indices $\geq 37$ for this task) are
merged only in the last few steps of the main loop, after all other
candidate pairs have been exhausted, rather than at step~1 as happened
before the fix (when \texttt{goal\_relevance} alone picked the axiom factor
immediately).

\paragraph{A second scoring function: \texttt{sf\_miasm}.} The fix is not
specific to the \texttt{goal\_relevance}/\texttt{dfp} scoring chain used
above. \texttt{sf\_miasm} (the scoring function behind ``dyn-MIASM'', which
favors merges that maximize the proportion of alive states in the resulting
product) only ever computes distances on a private, shrunk \emph{copy} of a
candidate product in order to score it --- it never touches the real
\texttt{fts}. The actual risk identified in \S\ref{sec:rootcause} lies in the
real \texttt{shrink\_before\_merge\_step} call applied to whichever pair is
finally selected, so \texttt{axiom\_deferral} must still be listed first in
the scoring chain even when \texttt{sf\_miasm} is used:

\begin{lstlisting}[language=bash, caption={Running phil01 with merge\_stateless + axiom\_deferral + sf\_miasm}]
./fast-downward.py \
    misc/tests/benchmarks/philosophers/domain.pddl \
    misc/tests/benchmarks/philosophers/p01-phil2.pddl \
    --search "astar(merge_and_shrink(
        merge_strategy=merge_stateless(
            merge_selector=score_based_filtering(
                scoring_functions=[axiom_deferral(),
                    sf_miasm(shrink_strategy=shrink_bisimulation(greedy=false),
                             max_states=50000,threshold_before_merge=1),
                    total_order(atomic_ts_order=reverse_level,
                                product_ts_order=new_to_old,
                                atomic_before_product=true)])),
        shrink_strategy=shrink_bisimulation(greedy=false),
        label_reduction=exact(before_shrinking=true,before_merging=false),
        max_states=50000,
        threshold_before_merge=1))"
\end{lstlisting}

The \texttt{shrink\_strategy}, \texttt{max\_states}, and
\texttt{threshold\_before\_merge} arguments to \texttt{sf\_miasm} are set to
match the planner's own M\&S options, as recommended by \texttt{sf\_miasm}'s
plugin documentation; the \texttt{total\_order} tie-break is the recipe from
the original dyn-MIASM paper. This configuration solved \texttt{phil01}
identically to the other two (cost~18, $h_{\mathrm{init}}=5$, 91 expanded, 0
dead ends), confirming \texttt{axiom\_deferral} composes correctly with a
second, independently implemented scoring function. As expected, it was
substantially slower ($\approx$21s main-loop runtime versus a fraction of a
second for \texttt{goal\_relevance}/\texttt{dfp}), since \texttt{sf\_miasm}
shrinks and computes distances on a candidate product for every remaining
merge pair at every step.

\paragraph{Status.} \texttt{merge\_stateless} is now considered safe to use
with axiom-derived factors, provided \texttt{axiom\_deferral} is listed first
among the scoring functions, regardless of which other scoring functions
follow it. \texttt{merge\_sccs} remains correct as well and needs no change.
Wider testing (larger Philosophers instances, other domains with derived
predicates) following the same plan as \S\ref{sec:nextsteps} is still
recommended before generalising this conclusion beyond the tested benchmark.

\subsection{Step 7 --- The Real Root Cause: a Frozen Atomic Factor for
Derived Variables}
\label{sec:step7}

\textbf{File:} \texttt{fts\_factory.cc}
(\texttt{FTSFactory::handle\_operator\_precondition}).

Step~6 made \texttt{merge\_stateless} work with axiom-derived factors by
\emph{avoiding} the suspected trigger (a premature partial axiom composite)
through \texttt{axiom\_deferral}. This section documents a second, distinct,
and more fundamental bug that was found afterwards while investigating
why \texttt{merge\_stateless} still produced a false
\emph{"Task is provably unsolvable"} on \texttt{p01-phil2} under some
configurations even with the Step~6 fixes in place. Fixing this bug at its
source makes \texttt{axiom\_deferral} unnecessary for this benchmark: with the
fix below, plain \texttt{merge\_stateless} -- using only
\texttt{score\_based\_filtering(goal\_relevance(), dfp(), total\_order())},
with no \texttt{axiom\_deferral} anywhere in the scoring chain -- solves
\texttt{p01-phil2} correctly.

\subsubsection{The Bug}

\texttt{FTSFactory::create\_transition\_systems} builds one naive
\emph{atomic} factor per task variable, including derived variables, before
any axiom-specific machinery runs. For each operator that has a precondition
on a variable $v$ but no effect on $v$, \texttt{handle\_operator\_precondition}
adds a self-loop transition that restricts the label to states where $v$
already holds the required value:
\begin{lstlisting}
if (!has_effect_on_var[var_id]) {
    int value = precondition.get_value();
    transitions_by_var[var_id].emplace_back(value, value);
    mark_as_relevant(var_id, label);
}
\end{lstlisting}
This is correct for a \emph{primary} variable: such a variable's value only
ever changes through operator effects, so gating the label on its
\emph{current} atomic-factor value is exact. It is \textbf{not} correct for a
\emph{derived} variable. A derived variable is never the target of an
operator effect -- its value is determined exclusively by axiom evaluation,
which is re-run after every operator application and depends on the
\emph{primary} variables in the derived variable's dependency closure
$S_d$. The naive atomic factor for a derived variable therefore never
changes state: it has exactly one reachable abstract state, frozen at the
variable's value in the initial state. Once
\texttt{handle\_operator\_precondition} adds the self-loop restriction above,
any label whose precondition references a derived variable becomes
permanently gated on whatever that variable's value happened to be
\emph{initially} -- even though the variable's true value changes constantly
as the plan progresses. If the derived variable's initial value differs from
the value some operator's precondition requires, that operator's label is
marked irrelevant/blocked in this atomic factor forever, and once this
atomic factor is merged into the rest of the FTS, the corresponding
operators become globally inapplicable in the abstraction -- producing
exactly the kind of false dead end described at a different level in
\S\ref{sec:rootcause}.

This is a strictly separate mechanism from the bisimulation-on-partial-
composite issue of \S\ref{sec:rootcause}: it does not involve
\texttt{build\_axiom\_factor}, \texttt{shrink\_before\_merge\_step}, or merge
order at all. It is purely a property of the naive, single-variable atomic
factor that \texttt{FTSFactory} builds for \emph{every} variable -- including
derived ones -- before any axiom-aware factor exists.

\subsubsection{The Fix}

The value-correlated precondition check for a derived variable is already
performed correctly elsewhere: \texttt{build\_axiom\_factor}
(\S\ref{sec:piece3}) constructs a dedicated product factor
$\Theta_{S,d}$ whose flat lookup table is computed from a full,
correct stratified axiom evaluation over $S_d$, and that factor's labels are
not artificially restricted by this code path. The derived variable's naive
\emph{atomic} factor therefore does not need to (and must not) impose any
restriction of its own; the fix is to make
\texttt{handle\_operator\_precondition} skip the self-loop restriction
whenever the precondition's variable is derived, leaving that label
irrelevant (self-looping on all values) in the atomic factor:
\begin{lstlisting}
void FTSFactory::handle_operator_precondition(
    OperatorProxy op, FactProxy precondition,
    const vector<bool> &has_effect_on_var,
    vector<vector<Transition>> &transitions_by_var) {
    int label = op.get_id();
    VariableProxy var = precondition.get_variable();
    int var_id = var.get_id();
    // Derived variables are never targeted by operator effects; their
    // value is determined by axiom evaluation over the variables in their
    // dependency closure, not by the (frozen) value in this naive atomic
    // factor. Gating a label on that frozen value would incorrectly block
    // it forever. The real, value-correlated check for this variable is
    // performed by the axiom-induced factor for its dependency closure.
    if (var.is_derived())
        return;
    if (!has_effect_on_var[var_id]) {
        int value = precondition.get_value();
        transitions_by_var[var_id].emplace_back(value, value);
        mark_as_relevant(var_id, label);
    }
}
\end{lstlisting}
The change is local to this one function and has no effect on tasks without
derived variables, since \texttt{var.is\_derived()} is always \texttt{false}
for primary variables.

With this fix alone (and without removing \texttt{axiom\_deferral}, which
remains available and harmless to use), \texttt{p01-phil2} is solved
correctly by \texttt{merge\_stateless} \emph{without} any
\texttt{axiom\_deferral} scoring function:
\begin{lstlisting}[language=bash, caption={merge\_stateless without axiom\_deferral, after the Step~7 fix}]

\paragraph{Relationship to Step 6.} This result indicates that, at least on
the tested benchmark, the atomic-factor bug fixed here was sufficient by
itself to explain the original \texttt{merge\_stateless} failure, and that
the bisimulation-on-partial-composite mechanism hypothesised in
\S\ref{sec:rootcause} -- while a real, theoretically sound concern in its own
right -- was not necessarily the operative cause of the specific dead end
observed on \texttt{p01-phil2}. The two mechanisms are independent and not
mutually exclusive: a task could in principle still trigger the
partial-composite issue even with the Step~7 fix applied, so
\texttt{axiom\_deferral} is kept in the codebase as a defence-in-depth option
rather than removed. It is, however, no longer a \emph{required} part of a
working \texttt{merge\_stateless} configuration for the benchmarks tested so
far.

\paragraph{Status.} The original goal of this investigation --
\texttt{merge\_stateless} working correctly on axiom tasks without relying on
\texttt{axiom\_deferral} -- is met for \texttt{p01-phil2}. As with Step~6,
wider testing (larger Philosophers instances, other domains with derived
predicates, and the \texttt{p02-phil3} instance that currently times out
during axiom-factor construction for unrelated scalability reasons) is
recommended before generalising this conclusion further.

\paragraph{Scope: this is a soundness fix, not full "axioms in preconditions"
support.} It is worth being precise about what this fix does and does not
deliver, since the two are easy to conflate. Before the fix, a derived
variable's naive atomic factor was actively \emph{unsound} whenever that
variable appeared in an operator precondition: it silently introduced the
false-restriction bug described above, regardless of whether the variable
was goal-relevant. After the fix, that same atomic factor is
\emph{sound but uninformative} for any derived variable not also covered by
a dedicated axiom factor from \texttt{build\_axiom\_factor}
(\S\ref{sec:piece3}) -- which at the time of this step was only invoked for
\emph{goal}-derived variables. A derived variable referenced only in operator
preconditions or conditional-effect conditions, never in the goal, therefore
still contributed nothing to the heuristic's value after this fix -- it was
correctly ignored rather than incorrectly restrictive. Step~9
(\S\ref{sec:step9}) extends \texttt{build\_axiom\_factor} to also cover
derived variables that appear in operator preconditions and
conditional-effect (\texttt{when}-clause) conditions.

\subsection{Step 8 --- Scalability Fix: Reachability Exploration Replaces Full
Product-Space Enumeration in \texttt{build\_axiom\_factor}}
\label{sec:step8}

\textbf{Files:} \texttt{fts\_factory.cc}, \texttt{merge\_and\_shrink\_representation.h/.cc}.

\subsubsection{The Problem: Cost Scales with the Full Product, Not With
What Is Reachable}

Steps~3 and~7 establish that \texttt{build\_axiom\_factor}
(\S\ref{sec:piece3}) builds $\Theta_{S,d}$, the axiom-induced product factor
over the primary-variable dependency closure $S_d$ of one or more derived
variables, by enumerating \emph{every} combination of values of the
variables in $S_d$ -- i.e.\ every one of
$\mathrm{num\_product\_states} = \prod_{v \in S_d} |\mathrm{dom}(v)|$ tuples
-- twice: once to evaluate the stratified axiom closure at each tuple (Step
4, goal-state marking) and once to compute, for every relevant operator,
its transition out of each tuple (Step 5, transition construction). This
cost is independent of how many of those tuples are actually reachable from
the initial state: a task can easily have a $S_d$ whose primary variables
admit millions of combinations of which only a small fraction ever occurs
in a reachable concrete state, because most combinations violate
constraints (mutexes, invariants) that are never explicit in the variables'
raw domains.

This is exactly what happens on the \texttt{optical-telegraphs}
\texttt{p01-opt2} benchmark. Each of its four goal-derived variables has a
dependency closure of $n = 14$ primary variables, giving
$\mathrm{num\_product\_states} \approx 3.77 \times 10^6$ per closure -- and
\texttt{build\_axiom\_factor} is invoked once per closure (four times for
this task). Before this fix, building the four axiom factors took roughly
\textbf{302\,s} and peaked at \textbf{4.80\,GB}, dwarfing every other part
of constructing the abstraction (the main M\&S loop and the subsequent
search together take only a few seconds once the axiom factors exist).
Table~\ref{tab:step8-before-after} below gives the measured per-variable
breakdown.

\subsubsection{The Fix: BFS From the Initial State}

The fix (commit \texttt{52e34ae}, ``Fix exponential blowup in
\texttt{build\_axiom\_factor} via reachability exploration'') replaces both
full-product loops with a single breadth-first exploration that starts at
the encoded initial state and follows only the relevant operators'
preconditions/effects, discovering exactly the product states that are
reachable -- nothing more. Two state identifiers are needed throughout:

\begin{itemize}
  \item the \emph{full} id: the same mixed-radix encoding as before
        (\S\ref{sec:piece3}, Step~2), used to index \texttt{decode\_val} and
        the sparse lookup table described below;
  \item the \emph{dense} id: a 0-based index assigned in BFS discovery
        order, used to number the states of the \texttt{TransitionSystem}
        being built (and, transitively, every abstract state the heuristic
        operates on downstream).
\end{itemize}

\begin{lstlisting}[language=C++, caption={Reachability exploration in \texttt{build\_axiom\_factor} (condensed)}]
unordered_map<int, int> full_to_dense;
vector<int> dense_to_full;
queue<int> frontier;

auto get_dense = [&](int full_state) -> int {
    auto it = full_to_dense.find(full_state);
    if (it != full_to_dense.end())
        return it->second;
    int new_id = static_cast<int>(dense_to_full.size());
    full_to_dense.emplace(full_state, new_id);
    dense_to_full.push_back(full_state);
    frontier.push(full_state);
    return new_id;
};

get_dense(init_full_state);

while (!frontier.empty()) {
    int s_full = frontier.front();
    frontier.pop();
    int s_dense = full_to_dense.at(s_full);

    for (const RelevantOperator &rop : relevant_ops) {
        // ... check rop.op_pre against decode_val(s_full, ...) as before ...
        // ... apply rop.effects to compute t_full as before ...
        int t_dense = get_dense(t_full);
        label_trans[rop.label].emplace_back(s_dense, t_dense);
        if (need_self_loop && t_dense != s_dense)
            label_trans[rop.label].emplace_back(s_dense, s_dense);
    }
}
int num_reachable_states = static_cast<int>(dense_to_full.size());
\end{lstlisting}

Operator preconditions/effects on $S_d$ variables are precomputed once per
\emph{relevant operator} before the BFS starts (a \texttt{RelevantOperator}/
\texttt{RelevantEffect} pair of structs), avoiding repeated re-derivation of
those projections from the \texttt{OperatorProxy} on every BFS pop. This
precomputation was already implicit in the pre-fix code, which also checked
relevance once per operator and skipped the per-state work entirely for
irrelevant ones -- so it does not by itself change the asymptotic cost on the
operator side, before or after the fix, the per-state work is proportional to
\texttt{num\_relevant\_ops}, not to the total number of operators in the
task. Goal-state evaluation (Step~4) is deferred until \emph{after} the BFS
completes and is then run only over the \texttt{num\_reachable\_states}
discovered states, instead of over every one of the
\texttt{num\_product\_states} full tuples. The real asymptotic win is
entirely on the \emph{state} side: visiting only reachable states instead of
the full product. The asymptotic cost of the whole construction therefore
changes from
\[
  O(\mathrm{num\_product\_states} \times \mathrm{num\_relevant\_ops})
  \quad\text{to}\quad
  O(\mathrm{num\_reachable\_states} \times \mathrm{num\_relevant\_ops}),
\]
with an analogous reduction in memory, since every per-state array built
during construction (\texttt{goal\_states}, the self-loop list for
irrelevant labels, the pending-value rows consumed by Step~6 of the main
loop) is now sized by \texttt{num\_reachable\_states} instead of
\texttt{num\_product\_states}.

\paragraph{The representation still needs the full product, just sparsely.}
\texttt{MergeAndShrinkRepresentationProduct::get\_value} (\S\ref{sec:piece1})
encodes a \emph{concrete} planning state directly via the mixed-radix
formula over $S_d$ and looks the result up in a flat table -- it has no way
to know in advance whether that formula will land on a state the BFS
visited. The lookup table therefore still has to be sized by
\texttt{num\_product\_states}, but it no longer needs to hold a distinct
abstract-state id for \emph{every} entry: a new constructor overload
builds it directly from the BFS results, marking every entry that is
\emph{not} one of the discovered \texttt{dense\_to\_full} ids as
\texttt{PRUNED\_STATE}, and seeding the representation's abstract domain
size to \texttt{num\_reachable\_states} instead of
\texttt{num\_product\_states}:
\begin{lstlisting}[language=C++, caption={Sparse lookup-table constructor, \texttt{merge\_and\_shrink\_representation.cc}}]
MergeAndShrinkRepresentationProduct::MergeAndShrinkRepresentationProduct(
    const vector<int> &var_ids, const vector<int> &domain_sizes,
    vector<int> initial_lookup_table, int num_live_states)
    : MergeAndShrinkRepresentation(num_live_states),
      var_ids(var_ids),
      multipliers(compute_product_multipliers(var_ids, domain_sizes)),
      lookup_table(move(initial_lookup_table)) {
}
\end{lstlisting}
This avoids the $O(\mathrm{num\_product\_states})$ identity-fill that the
original (dense) constructor performs, and -- crucially for
\texttt{Distances} and later shrinking, which size their own bookkeeping
from \texttt{get\_domain\_size()} -- avoids ever allocating anything
proportional to the full product size other than this one lookup table
itself.

\subsection{Step 9 --- Three Soundness Fixes on Domains with When-Clauses}
\label{sec:step9}

\textbf{Files:} \texttt{fts\_factory.cc},
\texttt{merge\_and\_shrink\_algorithm.cc},
\texttt{merge\_scoring\_function\_total\_order.cc}

\subsubsection{Background: When-Clauses and Derived Variables}

SAS$^+$ \emph{conditional effects} (PDDL \texttt{when}-clauses) appear in
the operator section of a \texttt{.sas} file as effect lines of the form

\begin{lstlisting}
<n_conds> <cond_var1> <cond_val1> ... <eff_var> <pre_val> <post_val>
\end{lstlisting}

with $n\_conds > 0$.  A \texttt{when}-clause fires only when all of its
conditions hold in the current state; otherwise the operator applies but the
effect is skipped.

Domains that use \texttt{when}-clauses often also have derived variables
(axioms) because both mechanisms arise from existential or conditional
reasoning in PDDL.  The interaction of the two features exposed three
soundness bugs in \texttt{build\_axiom\_factor} and the surrounding
infrastructure.  All three were found by testing on benchmark domains
containing \texttt{when}-clauses:

\begin{itemize}
  \item \texttt{misc/tests/benchmarks/sum/sum\_3.sas} — 36 derived
    variables at axiom layer~0, chained same-layer dependencies.
  \item \texttt{misc/tests/benchmarks/muddy-children/3-muddy.sas} — derived
    variables with same-layer chains, some operators with \texttt{when}-clauses.
  \item \texttt{misc/tests/benchmarks/muddy-child/3-muddy\_1.sas} — derived
    variables at axiom layer~0, operators with two independent
    \texttt{when}-clause effects on different product-space variables.
\end{itemize}

\subsubsection{Fix A — Axiom Closure Needs Fixpoint Iteration, Not a Single
Pass}
\label{sec:fix-a}

\paragraph{Symptom.}
\texttt{astar(merge\_and\_shrink(\ldots))} with exact bisimulation reported
\texttt{sum\_3.sas} as provably unsolvable, while \texttt{astar(blind())}
found a plan of cost~3.

\paragraph{Root cause.}
Step~4 of \texttt{build\_axiom\_factor} (the stratified forward-chaining
loop that marks goal states by evaluating axiom rules over each product
state) ran a single pass over \texttt{relevant\_axioms} sorted by axiom
layer.  The comment that justified this --- ``FD stratification prevents
intra-layer positive cycles'' --- was wrong in a subtle but important way.

FD's stratification rules forbid intra-layer \emph{negative} dependencies
(a rule at layer $\ell$ that conditions on the \emph{default} value of a
variable must be in a layer strictly higher than that variable's rule).
They impose no ordering constraint on intra-layer \emph{positive}
dependencies (a rule that conditions on the \emph{non-default} value of a
same-layer variable is legal).  As a result, two rules at the same layer
can legally form a chain: rule~$A$ fires only when derived variable~$d_1$
has been set (non-default), while rule~$B$ is the one that sets $d_1$.
Nothing in the stratification algorithm guarantees that rule~$B$ appears
before rule~$A$ in the axiom file; in \texttt{sum\_3.sas} the dependent
rule came first.  A single pass therefore evaluated rule~$A$ before rule~$B$
had fired, leaving $d_1$ at its default, so rule~$A$ was never satisfied and
the ultimate goal-derived variable was never set to its goal value.  The
result was zero goal states in every axiom factor, which the algorithm
interpreted as a provably unsolvable task.

\paragraph{Fix.}
Replace the single linear pass with a fixpoint loop.  Each iteration
re-evaluates all rules that have not yet fired.  The loop terminates as
soon as no new rule fires in a complete pass --- which is guaranteed within
at most $|\mathit{relevant\_axioms}|$ iterations because each derived
variable fires at most once (axioms are monotone: once set to a non-default
value the variable is never reset):

\begin{lstlisting}[language=C++, caption={Fixpoint axiom evaluation in \texttt{build\_axiom\_factor} (fts\_factory.cc)}]
bool changed = true;
while (changed) {
    changed = false;
    for (const AxiomRule &rule : relevant_axioms) {
        if (derived_vals[rule.eff_var] != derived_default.at(rule.eff_var))
            continue; // already fired; axioms fire at most once
        bool satisfied = true;
        for (auto [cvar, cval] : rule.conditions) {
            int cur_val;
            if (variables[cvar].is_derived()) {
                auto it = derived_default.find(cvar);
                cur_val = (it != derived_default.end())
                          ? derived_vals[cvar]
                          : variables[cvar].get_default_axiom_value();
            } else {
                auto it = var_id_to_idx.find(cvar);
                if (it == var_id_to_idx.end())
                    continue; // not in product space: over-approximate
                cur_val = decode_val(s_full, it->second);
            }
            if (cur_val != cval) { satisfied = false; break; }
        }
        if (satisfied) {
            derived_vals[rule.eff_var] = rule.eff_val;
            changed = true;
        }
    }
}
\end{lstlisting}

This replaces the previous single \texttt{for}-loop over
\texttt{relevant\_axioms} (which was identical except for lacking the outer
\texttt{while(changed)} wrapper and the \texttt{changed = true} assignment).

\subsubsection{Fix B — Partial-Firing Combinations for Multiple Independent
When-Clause Effects}
\label{sec:fix-b}

\paragraph{Symptom.}
After Fix~A, \texttt{sum\_3.sas} and \texttt{muddy-children/3-muddy.sas}
both matched \texttt{astar(blind())} in plan cost.
\texttt{muddy-child/3-muddy\_1.sas} became solvable (previously reported
unsolvable), but A$^*$ returned a plan of cost~5 while
\texttt{astar(blind())} found the optimal plan of cost~4.  Since exact
bisimulation should yield a heuristic equal to the true goal distance
(absent state-limit truncation), returning a worse-than-optimal plan implies
the heuristic \emph{overestimates} somewhere --- breaking admissibility.

\paragraph{Root cause.}
Step~5 of \texttt{build\_axiom\_factor} (reachability exploration) correctly
handles a \texttt{when}-clause effect whose condition references a variable
outside $S_d$ by both applying the effect (over-approximating that it fires)
and adding a self-loop (modelling the case where it does not).  However,
when a \emph{single operator} has \textbf{two or more} such effects, each
conditioned on a \emph{different} outside variable, the previous code only
generated two outcomes: ``all outside-conditioned effects fire'' (the
computed $t\_full$) and ``none fire'' (the self-loop).  It never generated
the intermediate cases where exactly one of the effects fires and the others
do not.

Because the conditions are on independent variables outside $S_d$, any
subset of them can hold in a real state.  The missing partial-firing
combinations are \emph{real, reachable transitions}; omitting them
\emph{under}-approximates the transition relation.  An
under-approximation can only make abstract distances longer than the true
distances --- the heuristic overestimates --- breaking admissibility and
causing A$^*$ to return a non-optimal plan.

\paragraph{Concrete example.}
In \texttt{muddy-child/3-muddy\_1.sas}, the axiom factor for derived
variable~40 has primary-variable dependency closure $S_{40} = \{7, 31, 19,
15\}$.  Operator \texttt{a\_asks\_b} has two effects on $S_{40}$ variables:
effect on $\mathit{var}_{31}$ conditioned on the derived variable
$\mathit{var}_{26} = 0$ (outside $S_{40}$), and effect on
$\mathit{var}_{19}$ conditioned on the derived variable $\mathit{var}_{10}
= 0$ (also outside $S_{40}$, and independent of $\mathit{var}_{26}$).  The
old code added only the ``both fire'' transition (setting both
$\mathit{var}_{31}$ and $\mathit{var}_{19}$ to~0) and the ``neither fires''
self-loop.  The cases ``$\mathit{var}_{26} = 0$ but $\mathit{var}_{10} \ne
0$'' and ``$\mathit{var}_{10} = 0$ but $\mathit{var}_{26} \ne 0$'' were
missing, leaving the abstraction unable to reach certain concrete states
where only one of the two variables was zeroed by \texttt{a\_asks\_b}.

\paragraph{Fix.}
Enumerate every subset of the ``active'' (self-conditions satisfied)
outside-conditioned effects per operator application, and add the
corresponding transition for each subset.  If there are $k$ such effects,
$2^k$ transitions are generated (one per subset, including the empty subset,
which is the self-loop).  In practice $k$ is very small (the operator must
have multiple relevant effects each with a different outside condition), so
the $2^k$ factor is harmless.

\begin{lstlisting}[language=C++, caption={Subset enumeration for outside-conditioned effects (fts\_factory.cc)}]
vector<bool> effect_active(rop.effects.size());
vector<int> optional_effect_positions;
for (size_t i = 0; i < rop.effects.size(); ++i) {
    const RelevantEffect &re = rop.effects[i];
    bool fires = true;
    for (int cval : re.self_cond_vals) {
        if (decode_val(s_full, re.idx) != cval) { fires = false; break; }
    }
    effect_active[i] = fires;
    if (fires && re.has_outside_cond)
        optional_effect_positions.push_back(i);
}

int num_subsets = 1 << optional_effect_positions.size();
for (int subset = 0; subset < num_subsets; ++subset) {
    vector<bool> optional_fires(rop.effects.size(), false);
    for (size_t b = 0; b < optional_effect_positions.size(); ++b)
        if (subset & (1 << b))
            optional_fires[optional_effect_positions[b]] = true;

    int t_full = s_full;
    for (size_t i = 0; i < rop.effects.size(); ++i) {
        if (!effect_active[i]) continue;
        const RelevantEffect &re = rop.effects[i];
        if (re.has_outside_cond && !optional_fires[i]) continue;
        t_full -= decode_val(t_full, re.idx) * mult[re.idx];
        t_full += re.post * mult[re.idx];
    }
    int t_dense = get_dense(t_full);
    label_trans[rop.label].emplace_back(s_dense, t_dense);
}
\end{lstlisting}

This replaces the previous block that computed a single $t\_full$ (all
outside-conditioned effects applied unconditionally) and then added a
self-loop if \texttt{need\_self\_loop} was set.  The new code subsumes the
old: subset~$0$ (no optional effect fires) always produces the self-loop
transition $s \to s$, and the full subset (all optional effects fire) produces
the original $t\_full$.  When $k = 0$ (no outside-conditioned effects), there
is exactly one subset (the empty one), and the loop degenerates to the same
single transition as before.

\subsubsection{Fix C --- Build Axiom Factors for Non-Goal Derived Variables
Referenced by Operators}
\label{sec:fix-c}

\paragraph{Symptom.}
In domains where a \texttt{when}-clause condition (or an operator precondition)
references a derived variable that is \emph{not} itself a goal variable,
\texttt{build\_axiom\_factor} was never invoked for that derived variable.
Its naive atomic factor (built by \texttt{FTSFactory::create\_transition\_systems}
for every variable) was therefore left as the sole representation of that
variable in the FTS.  That atomic factor never changes state through operators
(derived variables have no operator effects), so the associated operators
appeared permanently inapplicable or their \texttt{when}-clauses appeared to
never fire, making a solvable task appear unsolvable.

\paragraph{Fix.}
Extend the set of derived variables for which axiom factors are built from
``goal-derived variables only'' to ``all derived variables that are either a
goal variable, an operator precondition variable, or a condition variable of a
\texttt{when}-clause effect''.  Derived variables with zero axiom rules are
excluded regardless (they are translator-introduced constants whose atomic
factor is already exact).

A new helper \texttt{collect\_relevant\_derived\_variables} in
\texttt{merge\_and\_shrink\_algorithm.cc} computes this set:

\begin{lstlisting}[language=C++, caption={Collecting all derived variables that need axiom factors (merge\_and\_shrink\_algorithm.cc)}]
static vector<int> collect_relevant_derived_variables(
    const TaskProxy &task_proxy) {
    int num_variables = task_proxy.get_variables().size();
    vector<bool> needs_axiom_factor(num_variables, false);

    for (FactProxy goal : task_proxy.get_goals())
        if (goal.get_variable().is_derived())
            needs_axiom_factor[goal.get_variable().get_id()] = true;

    for (OperatorProxy op : task_proxy.get_operators()) {
        for (FactProxy pre : op.get_preconditions())
            if (pre.get_variable().is_derived())
                needs_axiom_factor[pre.get_variable().get_id()] = true;
        for (EffectProxy eff : op.get_effects())
            for (FactProxy cond : eff.get_conditions())
                if (cond.get_variable().is_derived())
                    needs_axiom_factor[cond.get_variable().get_id()] = true;
    }

    vector<bool> has_axiom_rule(num_variables, false);
    for (OperatorProxy axiom : task_proxy.get_axioms())
        has_axiom_rule[axiom.get_effects()[0].get_fact()
                           .get_variable().get_id()] = true;

    vector<int> result;
    for (int var_id = 0; var_id < num_variables; ++var_id)
        if (needs_axiom_factor[var_id] && has_axiom_rule[var_id])
            result.push_back(var_id);
    return result;
}
\end{lstlisting}

The \texttt{build\_factored\_transition\_system} function is updated to call
this helper instead of iterating over goal variables directly, and the
\texttt{has\_derived\_goals} boolean is replaced by
\texttt{has\_relevant\_derived\_vars}:

\begin{lstlisting}[language=C++, caption={Using the extended set in build\_factored\_transition\_system}]
vector<int> derived_vars_needing_axiom_factor =
    collect_relevant_derived_variables(task_proxy);
bool has_relevant_derived_vars = !derived_vars_needing_axiom_factor.empty();
// ...
if (has_relevant_derived_vars) {
    ShrinkQuasiBisimulation qbisim;
    for (int derived_var_id : derived_vars_needing_axiom_factor) {
        // build and shrink axiom factor as before ...
    }
}
\end{lstlisting}

\texttt{build\_axiom\_factor} is updated to allow non-goal derived variables
as targets: \texttt{assert(goal\_derived\_value != -1)} is replaced by a
boolean flag \texttt{is\_goal\_var}, and the goal-state assignment becomes:

\begin{lstlisting}[language=C++]
bool is_goal_var = (goal_derived_value != -1);
// ... (axiom evaluation unchanged) ...
goal_states[d] = !is_goal_var ||
                 (derived_vals[derived_var_id] == goal_derived_value);
\end{lstlisting}

When \texttt{is\_goal\_var} is false, every product state is a local goal
state for this factor, and all goal-distance constraints are enforced by
the other factors that do have real goal values.

A matching \texttt{count\_relevant\_derived\_variables} helper is added to
\texttt{merge\_scoring\_function\_total\_order.cc} to keep the precomputed
merge order in sync with the actual number of initial factors, avoiding the
\texttt{assert(scores.size() == candidate\_index + 1)} failure that would
result from undercounting (the same class of bug as Bug~2 in Step~3,
\S\ref{sec:piece4}).

\paragraph{Relationship to the three commit-message points and \texttt{when}-clauses.}
All three fixes concern domains with \texttt{when}-clauses, but in different
ways:

\begin{itemize}
  \item \textbf{Fix~A (fixpoint)} addresses axiom rules that chain at the
    same layer --- a dependency structure that commonly arises in domains
    with derived predicates, whether or not those predicates also appear in
    \texttt{when}-clauses.

  \item \textbf{Fix~B (subset enumeration)} is directly caused by
    \texttt{when}-clause effects in operators.  Each conditional-effect
    line with a condition on a different outside-$S_d$ derived variable
    contributes one independent ``bit'' to the subset.  The bug only
    manifests when two or more such \texttt{when}-clauses appear on the
    same operator and target different product-space variables.

  \item \textbf{Fix~C (non-goal derived variables)} is also directly
    connected to \texttt{when}-clauses: the conditions of a
    \texttt{when}-clause in PDDL/SAS$^+$ can reference derived predicates
    that never appear in the goal.  Without Fix~C those derived variables
    lacked real axiom factors and their operators were permanently blocked
    in the abstraction.
\end{itemize}

\subsubsection{Theoretical Grounding: All Three Fixes and the Reconstruction
Property}
\label{sec:when-clause-theory}

The three fixes above restore soundness at the implementation level; this
section explains why they are required at the formal level, connecting each
fix to the reconstruction property stated in \S\ref{sec:core-idea}.

\paragraph{The reconstruction property and its two requirements.}

The reconstruction property guarantees that $\Theta_{S_d,d}$, combined
with the individual atomic factors, recovers the full axiom language of
the synchronized product:

\[
  \Bigl(\bigcap_{\Theta_i \in S} \mathcal{L}((\Theta_i^G)^A)\Bigr)
  \;\cap\;
  \mathcal{L}(\Theta_{S,d})
  \;=\;
  \mathcal{L}\!\Bigl(\bigl(\bigotimes_{\Theta_i \in S} \Theta_i\bigr)^{\!A}\Bigr).
\]

For this to hold, $\Theta_{S_d,d}$ must satisfy two correctness conditions
simultaneously:

\begin{enumerate}
  \item \textbf{Goal states must be an over-approximation.}  Every product
    state where the true axiom closure makes $d$ true must be marked as a
    goal.  An under-approximation of the goal set (missing goal states)
    makes abstract distances to those states appear infinite or larger than
    reality --- the heuristic overestimates, breaking admissibility.

  \item \textbf{Transitions must be an over-approximation.}  Every
    transition reachable in some real state must have a corresponding edge
    in the abstract factor.  An under-approximation of the transition
    relation (missing edges) makes some product states unreachable in the
    abstraction even though they are reachable in reality --- again making
    abstract distances longer than the true distances and the heuristic
    overestimate.
\end{enumerate}

In both cases, an over-approximation is the safe direction: extra goal
states or extra transitions can only make abstract distances \emph{shorter},
so the heuristic \emph{underestimates} --- the admissibility condition.
All three bugs were under-approximations, each violating one of these two
conditions.

\paragraph{Fix~A --- under-approximation of the goal set.}

Step~4 of \texttt{build\_axiom\_factor} marks goal states by evaluating
the axiom rules over each product state: the $(\cdot)^A$ transformation
applied to the product space.  A single linear pass over the relevant
axioms is sufficient only if every rule's dependency has already fired
before the rule is evaluated.  FD's stratification forbids intra-layer
\emph{negative} cycles but permits intra-layer \emph{positive} chains,
meaning a rule can legally condition on a same-layer derived variable
that the file happens to list later.  When this occurs, the dependent
rule is evaluated before its dependency has fired, leaving the derived
variable at its default value and the rule unsatisfied.

The consequence is an under-approximation of the goal set: product
states where $d$ would genuinely evaluate to true are left unmarked.
With zero reachable goal states in an axiom factor (as happened for
every factor in \texttt{sum\_3.sas}), the algorithm declares the task
provably unsolvable even when a plan exists.  Fix~A replaces the single
pass with a fixpoint loop that re-evaluates rules until no new variable
fires, guaranteeing that the $(\cdot)^A$ transformation is applied
correctly regardless of rule ordering.

Fix~A is \emph{independent} of \texttt{when}-clauses.  It concerns the
axiom stratification layer, not conditional operator effects.  The bug
would arise in any domain whose axiom rules contain a same-layer positive
dependency chain, with or without \texttt{when}-clauses.  The indirect
connection to \texttt{when}-clause domains is that Fix~B (below) determines
\emph{which} product states are reachable via the transition relation, and
Fix~A then ensures that each of those reachable states is correctly
evaluated for goal membership.  The two fixes act on different phases of
building $\Theta_{S_d,d}$ --- goal-state marking and transition-relation
construction respectively --- and both are required for the reconstruction
property to hold.

\paragraph{Fix~B --- under-approximation of the transition relation (when-clause
effects).}

Step~5 of \texttt{build\_axiom\_factor} builds the transition relation
from planning operators.  When an operator's \texttt{when}-clause effect
is conditioned on a variable \emph{inside} $S_d$, the product state
encodes that variable's value and the decision is deterministic: the
effect definitively fires or does not fire.  When the condition references
a variable \emph{outside} $S_d$, the product state carries no information
about it; the correct response is to over-approximate by generating all
outcomes.

For a \emph{single} outside-conditioned effect, two outcomes suffice:
a forward edge $s \to t$ (effect fires) and a self-loop $s \to s$
(effect does not fire).  Step~5 handled this correctly from the start.
For \emph{two or more} outside-conditioned effects, each on a
\emph{different} outside variable, the conditions are independent and
any subset of them can hold in a real state: $k$ such effects require
$2^k$ transitions.  The pre-Fix~B code generated only two outcomes
regardless of $k$, silently dropping the $2^k - 2$ intermediate subsets.
Those missing transitions under-approximate the reachable product states,
inflate abstract distances, and break admissibility.

Fix~B enumerates all $2^k$ subsets.  Subset $\emptyset$ produces the
self-loop; the full subset produces the ``all fire'' transition; the
intermediate subsets produce the previously missing partial-firing
transitions.  For $k = 0$ a single subset degenerates to the original
unconditional transition, preserving backwards compatibility.

\paragraph{Fix~C --- under-approximation of the transition relation (missing
axiom factors).}

A derived variable $d'$ that appears only in an operator precondition or
\texttt{when}-clause condition --- but not in the goal --- was previously
left without a real axiom factor.  Its atomic factor (built by
\texttt{FTSFactory} for every variable) has no operator transitions, so
it stays frozen at its initial value throughout the search.  Any operator
whose precondition requires $d'$ to hold a non-initial value appears
permanently inapplicable in the abstraction; any operator whose
\texttt{when}-clause conditions on $d'$ appears as if the clause never
fires.  Both effects remove real transitions from the abstract factor,
under-approximating the transition relation and again making abstract
distances longer than the true distances.

Fix~C extends the set of derived variables for which axiom factors are
built to include all variables referenced in operator preconditions or
\texttt{when}-clause conditions.  This replaces the under-approximation
(operator transitions entirely absent) with an over-approximation:
since $d'$ is a derived variable and therefore never a member of any
factor's primary variable set $S_d$, its precondition value is still
not checkable inside \texttt{build\_axiom\_factor}, so operators that
condition on $d'$ continue to be treated as applicable regardless of
$d'$'s value.  The key difference is that this is now an
\emph{over}-approximation --- operators may fire when they should not ---
rather than an under-approximation where they could never fire at all.
Over-approximating is the safe direction for admissibility.

It is important to note that Fix~C is \emph{not} a full implementation
of axioms in operator preconditions.  A complete treatment would require
correctly restricting operator applicability based on derived preconditions
--- for example, by tracking $d'$ jointly with the other primary variables
in the axiom factor, or by relying on the M\&S merging of the new axiom
factors to propagate the restriction.  Fix~C is a necessary prerequisite
(the axiom factor for $d'$ must exist before the M\&S loop can merge it),
but the precise modelling of derived preconditions in operator applicability
remains future work.

\paragraph{How the three fixes fit together.}

In plain terms, building a correct abstract factor $\Theta_{S_d,d}$ has
three independent concerns, and each fix corrects exactly one of them.
Fix~C answers \emph{which factors to build}: it ensures that every derived
variable the task actually depends on --- not just those that appear
directly in the goal --- gets a real axiom factor, so that operators
referencing those variables are not incorrectly blocked.  Fix~A answers
\emph{which states are goals}: once a factor exists, each of its product
states must be tested by running the axiom rules to a fixpoint, because a
single linear pass can miss same-layer dependencies and leave genuinely
reachable goal states unmarked.  Fix~B answers \emph{what the transitions
are}: for operators with \texttt{when}-clause effects conditioned on
variables outside the factor, every combination of those effects firing
independently must be represented as a separate transition, not just the
two extremes of all firing or none firing.  A mistake in any one of these
three aspects produces an under-approximation that inflates abstract
distances and breaks admissibility --- which is why all three bugs had to
be fixed together before the benchmarks produced correct, optimal plans.

\paragraph{Summary.}

Each fix addresses a distinct under-approximation that violates the
reconstruction property:

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Fix} & \textbf{What was under-approximated} & \textbf{Effect on heuristic} \\
\midrule
Fix~A & Goal set ($(\cdot)^A$ transformation) & Overestimates (false unsolvable) \\
Fix~B & Transition relation (when-clause subsets) & Overestimates (suboptimal plan) \\
Fix~C & Transition relation (missing axiom factors) & Overestimates (false unsolvable) \\
\bottomrule
\end{tabular}
\end{center}

With all three fixes in place, both the goal set and the transition
relation of $\Theta_{S_d,d}$ are genuine over-approximations.  The
reconstruction property is satisfied, and exact bisimulation shrinking
produces a heuristic that is both admissible and --- in the absence of
state-limit truncation --- equal to the true goal distance.

\subsection{Phased Implementation Path}

\hrule\medskip
\noindent\textbf{Phase 1 — Axioms in goal conditions \hfill\textit{[Complete]}}
\medskip

Phase 1 adds support for tasks whose \emph{goal} is a derived predicate.  The
key idea is to build an extra abstract factor for each derived goal variable,
compute its quasi-bisimulation quotient, and include it alongside the
primary-variable factors in the M\&S heuristic.

The following was implemented:

\begin{itemize}
  \item \textbf{Primary representations} (\texttt{primary\_representation.h/.cc}):
    for each derived goal variable~$d$, identify the set $S_d$ of primary
    (non-derived) variables that $d$ depends on transitively.
  \item \textbf{Axiom-induced factors} (\texttt{fts\_factory.cc}): build a
    product transition system over $S_d$, then evaluate the axiom rules to
    mark which abstract states satisfy the derived goal.
  \item \textbf{Quasi-bisimulation shrinking}
    (\texttt{shrink\_quasi\_bisimulation.cc}): reduce each axiom-induced factor
    while preserving goal/non-goal distinctions and admissibility of the
    heuristic.
  \item \textbf{Main loop integration}
    (\texttt{merge\_and\_shrink\_algorithm.cc},
    \texttt{merge\_and\_shrink\_heuristic.cc}): removed the axiom abort,
    appended axiom-induced factors to the factored transition system before the
    main M\&S loop begins, and updated the language-support annotation to
    \texttt{"supported"}.
\end{itemize}

\label{sec:nextsteps}
\textbf{Next steps for Phase~1.}
The implementation has been validated on the Philosophers benchmark
(see the table in Step~5).  To build further confidence it should be tested on
a wider range of domains:

\begin{itemize}
  \item \emph{More Philosophers instances} — larger instances
    (\texttt{phil04}, \texttt{phil05}, \ldots) to check scalability and ensure
    dead-end counts remain genuine.
  \item \emph{Other IPC domains with derived predicates} — for example
    \texttt{psr-small}, \texttt{optical-telegraphs}, and \texttt{philosophers}
    variants from the downward-benchmarks repository, which cover a variety of
    axiom-dependency structures.
  \item \emph{Regression check} — run a selection of non-axiom domains (e.g.\
    \texttt{gripper}, \texttt{logistics}) to confirm that the changes do not
    affect performance on tasks without derived predicates.
\end{itemize}

\bigskip
\hrule\medskip
\noindent\textbf{Phase 2 — Axioms in operator preconditions \hfill\textit{[In Progress]}}
\medskip

Phase~1 handles derived predicates that appear in the \emph{goal}.  Many
planning domains also use derived predicates in \emph{operator preconditions}:
an operator is applicable only when a derived variable holds a particular value.
Phase~2 extends the M\&S heuristic to model this restriction correctly.

Fix~C (Step~9) is a prerequisite that is already in place: axiom-induced
factors are built for every derived variable referenced in operator
preconditions, not only those in the goal.  What is still missing is the
\emph{applicability restriction}: operators conditioned on a derived
variable~$d'$ are currently over-approximated (assumed applicable regardless of
$d'$'s value).  The three steps below remove this over-approximation.  Once
$\Theta_{S_{d'},d'}$ correctly blocks an operator in non-goal states (where $d'$
is false), the M\&S synchronized-product semantics propagates the restriction
automatically to every factor that is eventually merged with it.

    its \texttt{axiom\_layer} (in the \texttt{begin\_variable} block) is
    non-negative; any operator listing such a variable as a precondition is a
    Phase~2 case.  Verify each candidate by checking that \texttt{astar(blind())}
    finds a plan while the current M\&S implementation either fails or returns a
    wrong cost.

  \item \textbf{Step 2 — Extend the relevant-operator set}
    (\texttt{fts\_factory.cc}, \texttt{build\_axiom\_factor}, operator-relevance
    check).
    Currently an operator is relevant to $\Theta_{S_{d'},d'}$ only if it has a
    precondition or effect on a variable in $S_{d'}$.  Operators whose only
    connection to the factor is a derived precondition on $d'$ are classified as
    irrelevant and receive a blanket self-loop in every state --- which
    incorrectly makes them appear always applicable.  Add a second relevance
    condition: an operator is relevant if its derived precondition is $d'$
    itself.  Such operators then receive a self-loop in goal states (applicable,
    no $S_{d'}$ variable changes) and \emph{no transition} in non-goal states
    (inapplicable).

    \medskip
    \noindent\textit{Result.}
    Step~2 is complete.  The implementation, testing on the \texttt{grid-axioms}
    domain, and the bugs discovered and fixed during testing are described below.

    \paragraph{Implementation.}
    Three targeted changes were made to \texttt{build\_axiom\_factor} in
    \texttt{fts\_factory.cc}:

    \begin{enumerate}
      \item \textbf{\texttt{has\_derived\_pre} flag.}
        The \texttt{RelevantOperator} struct gained a boolean field
        \texttt{has\_derived\_pre} (default \texttt{false}).  A set
        \texttt{target\_derived\_set} is built from the derived variable IDs
        of the factor being constructed to enable $O(1)$ lookup.  During the
        operator-relevance scan, any operator that (i)~has no precondition or
        effect on a primary variable in $S_{d'}$, but (ii)~has a precondition
        on a target derived variable, is marked relevant with
        \texttt{has\_derived\_pre = true}.

      \item \textbf{Skip during BFS.}
        The reachability BFS that explores product states skips every operator
        with \texttt{has\_derived\_pre = true}.  At BFS time the goal states
        have not yet been computed (they are determined by the fixpoint axiom
        evaluation of Fix~A in Step~9), so adding transitions for these
        operators would be premature.

      \item \textbf{Post-BFS self-loops in goal states.}
        After the goal-state vector is computed, a second pass iterates over
        all \texttt{has\_derived\_pre} operators.  For each such operator, a
        self-loop $(s, s)$ is added under that operator's label for every goal
        state $s$.  Non-goal states receive no transition, encoding that the
        operator is inapplicable when the derived precondition $d'$ is false.
    \end{enumerate}

    This is an \emph{exact} model of operator applicability with respect to
    the derived precondition: an operator conditioned on $d'$ can fire only in
    states where $d' = \mathrm{true}$, i.e.\ where the axiom factor is in a
    goal state.  The self-loop models the fact that the operator leaves $S_{d'}$
    variables unchanged when it fires.

    \paragraph{Testing on \texttt{grid-axioms} p01.}

    The \texttt{grid-axioms} domain uses a derived predicate \texttt{reachable}
    as an operator precondition (e.g.\ \texttt{unlock} requires the player to be
    at a reachable cell, modelled by the derived variable being true).  Running
    \texttt{astar(blind())} on \texttt{p01} finds a plan of cost~4 (actions:
    \texttt{pickup}, \texttt{unlock}, \texttt{pickup-and-loose}, \texttt{putdown}).

    Four bugs were discovered and fixed during testing.

    \paragraph{Bug 1 --- Integer overflow in product state IDs.}
    \textbf{Symptom.}  The planner crashed with SIGSEGV during
    ``Building atomic transition systems''.

    \textbf{Root cause.}  The \texttt{grid-axioms} \texttt{p01} instance has
    $n = 32$ primary variables in the dependency closure $S_d$ of the
    \texttt{reachable} derived variable.  The full product domain size is
    $\prod_{i} |\mathrm{dom}(x_i)| = 2^{32} \approx 4 \times 10^9$, which
    exceeds the range of a signed 32-bit integer ($2^{31} - 1 \approx 2.1
    \times 10^9$).  The mixed-radix multipliers and state IDs were stored as
    \texttt{int}, so the overflow silently wrapped and produced invalid
    (negative or zero) indices.

    \textbf{Fix.}  Two related changes were applied:
    \begin{itemize}
      \item In \texttt{fts\_factory.cc}: the \texttt{mult} array was changed
        from \texttt{vector<int>} to \texttt{vector<long long>}; the
        \texttt{full\_to\_dense} hash map key type, the \texttt{dense\_to\_full}
        vector element type, the \texttt{frontier} queue element type, and
        \texttt{init\_full\_state} were all changed from \texttt{int} to
        \texttt{long long}.
      \item In \texttt{merge\_and\_shrink\_representation.h/.cc}: the
        \texttt{multipliers} member of
        \texttt{MergeAndShrinkRepresentationProduct} was changed to
        \texttt{vector<long long>}; the flat \texttt{vector<int>} lookup table
        was replaced by a sparse \texttt{unordered\_map<long long, int>} so
        that only reachable product states need entries (allocating a flat
        table of $2^{32}$ entries is infeasible).  The \texttt{get\_value}
        method encodes the concrete state's variable values as a \texttt{long
        long} product-state ID via \texttt{multipliers} and uses
        \texttt{unordered\_map::find}; absent entries (unreachable or pruned
        states) return \texttt{PRUNED\_STATE}.
    \end{itemize}

    \paragraph{Bug 2 --- SIGSEGV in \texttt{MergeAndShrinkRepresentationLeaf}.}
    \textbf{Symptom.}  A second SIGSEGV appeared after Bug~1 was fixed,
    again during ``Building atomic transition systems''.

    \textbf{Root cause.}  While modifying the \texttt{Product} representation
    class, the \texttt{MergeAndShrinkRepresentationLeaf} constructor was
    accidentally changed from the original \texttt{lookup\_table(domain\_size)}
    initialisation (which allocates a vector of size \texttt{domain\_size})
    followed by \texttt{std::iota}, to an empty default construction followed
    by a for-loop that indexed into the empty \texttt{vector<int>}, causing an
    out-of-bounds write.

    \textbf{Fix.}  The Leaf constructor was reverted to its original form:
    initialise \texttt{lookup\_table} with \texttt{domain\_size} elements and
    fill with \texttt{std::iota(lookup\_table.begin(), lookup\_table.end(), 0)}.

    \paragraph{Bug 3 --- BFS scalability: 18\,GB memory consumption.}
    \textbf{Symptom.}  After Bug~1 and Bug~2 were fixed the planner hung at
    ``Building axiom factor for derived variable~0''.  After approximately
    600\,000 BFS steps (3.7 million states discovered), the process had
    consumed over 18\,GB of memory and had to be killed.

    \textbf{Root cause.}  With $n = 32$ primary variables and 2214 relevant
    operators, the BFS explores a very large fraction of the full product space.
    Even though the overflow is fixed, the sheer size of the reachable state
    space makes the BFS computationally infeasible within practical memory and
    time budgets.

    \textbf{Fix (two-tier).}
    \begin{enumerate}
      \item \textbf{Fast-path check.}  At the start of
        \texttt{build\_axiom\_factor}, before any BFS begins, if the number
        of primary variables $n > 25$ (product space $> 2^{25} \approx
        33 \times 10^6$), return $-1$ immediately without starting the BFS.
        On \texttt{grid-axioms} \texttt{p01}, all 25 derived variables have
        $n = 32$ and hit this fast-path, eliminating 25 expensive BFS attempts
        (each would have taken $\approx$\,1.1\,s for a total of $\approx$\,27\,s
        before the fix).
      \item \textbf{State-limit safety net.}  As a fallback for closures just
        below the fast-path threshold, the BFS loop checks the count of
        discovered states at each pop and returns $-1$ if it exceeds 100\,000.
    \end{enumerate}

    \textbf{Admissibility.}  When \texttt{build\_axiom\_factor} returns $-1$,
    no factor is added to the FTS for that derived variable.  The derived
    variable's atomic factor already has all states marked as goals (from the
    \texttt{goal\_value = -1} fix in \hyperlink{par:step3-bug1}{Bug~1 of Step~3}), so the heuristic treats
    every concrete state as satisfying the derived constraint.  This is an
    over-approximation: the heuristic can only underestimate, preserving
    admissibility.

    \paragraph{Bug 4 --- Crash when \texttt{build\_axiom\_factor} returns $-1$.}
    \textbf{Symptom.}  After the fast-path was added, the planner crashed
    immediately because the caller in \texttt{merge\_and\_shrink\_algorithm.cc}
    passed the returned value $-1$ to \texttt{fts.get\_transition\_system} (an
    invalid index), causing a crash inside the quasi-bisimulation shrinking step.

    \textbf{Fix.}  The quasi-bisimulation shrinking and pending-variable tracking
    code that follows \texttt{build\_axiom\_factor} was wrapped in a guard:
\begin{lstlisting}[language=C++]
int axiom_index = build_axiom_factor(
    task_proxy, derived_var_id, fts, log);
// Returns -1 if the product space is too large to explore.
// Skip shrinking and variable tracking in that case.
if (axiom_index >= 0) {
    StateEquivalenceRelation equiv =
        qbisim.compute_equivalence_relation(
            fts.get_transition_system(axiom_index),
            fts.get_distances(axiom_index),
            max_states_before_merge, log);
    fts.apply_abstraction(axiom_index, equiv, log);
    // ... pending variable tracking ...
}
\end{lstlisting}

    With all four bugs fixed, \texttt{astar(merge\_and\_shrink(\ldots))}
    with exact bisimulation finds the same optimal plan as blind search:

    Step~2's self-loop / no-transition treatment is sound, and that the
    admissibility argument for skipping large axiom factors is valid.  Phase~2
    Steps~3--5 will address the remaining precision once the scalability of
    factor construction for large dependency closures is resolved.

    \paragraph{Further testing on \texttt{miconic-axioms} p01.}

    The \texttt{miconic-axioms} domain is a cleaner test of Phase~2
    Step~2 because its derived variable dependency closures are small (one
    primary variable each), so the axiom factors are actually built and used
    rather than skipped.  The instance \texttt{p01} has 5 planning variables

    \end{itemize}
    Both BFS runs complete immediately ($n = 1$ is well below the 25-variable
    fast-path threshold).  After quasi-bisimulation shrinking, the two axiom
    factors are appended at indices~5 and~6, giving 7 initial factors that are
    merged in 6 steps to a single final factor.  Maximum intermediate
    abstraction size is 4 states.

  \item \textbf{Step 3 — Restrict transitions to goal states}
    (\texttt{fts\_factory.cc}, \texttt{build\_axiom\_factor},
    transition-building loop).
    The \texttt{goal\_states} vector is already computed before the
    transition-building loop (by the fixpoint in Fix~A).  For each product
    state~$s$ and each relevant operator~$\mathit{op}$ whose derived precondition
    matches $d'$: if $s$ is \emph{not} a goal state, skip the transition
    entirely rather than adding it.  This turns the over-approximation into an
    exact model of operator applicability for $d'$.

  \item \textbf{Step 4 — Exact evaluation in factors where
    $S_{d'} \subseteq S_d$}
    (\texttt{fts\_factory.cc}, \texttt{build\_axiom\_factor}, applicability
    check).
    When building $\Theta_{S_d,d}$ for a \emph{different} derived variable $d$
    and operator $\mathit{op}$ has derived precondition $d'$: if $S_{d'}
    \subseteq S_d$, the product state already encodes all primary variables that
    determine $d'$, so run the axiom evaluator to decide $d'$'s truth and
    restrict $\mathit{op}$ accordingly (exact model).  If $S_{d'} \not\subseteq
    S_d$, keep the current over-approximation; the M\&S merging with
    $\Theta_{S_{d'},d'}$ will add the restriction later.

  \item \textbf{Step 5 — Validation}.
    Run \texttt{astar(merge\_and\_shrink(\ldots))} with exact bisimulation on
    the Phase~2 benchmark instances found in Step~1.  The plan cost must match
    \texttt{astar(blind())} on every instance; any discrepancy indicates a
    remaining soundness issue.  Also run the Phase~1 benchmark set as a
    regression check to confirm that the changes do not affect performance on
    domains whose operators have no derived preconditions.
\end{itemize}
